# Round 07 — 전투의 보드 패널 (하단 패널, 얼굴, 띠 아이콘)

전투 화면의 아이템 칸을 명패 아래의 세로 칸에서 **화면 아래의 보드 패널**로 옮긴 라운드다. 목업으로 정했고(A안), 얼굴 열하나는 전신 그림에서 잘라 냈으며(호출 없음),
2칸과 3칸의 아이템 아이콘 셋을 가로 띠로 다시 그렸다(호출 3회). 화면의 규칙은 `Docs/Architecture/12_UI.md` "전투 화면", 파이프라인은 `13_ART_PIPELINE.md`("후처리 (`cell`)", "얼굴")가 가진다.

- "현재 전투 ui에서 변경 부분 검토 — 세로로 나타냈던 아이템 방식을 가로형으로 전환 / 밑에 다키스트 던전 처럼 하단부를 차지하는 ui 패널을 넣고 캐릭터 별로(열 순서) 가로 아이템 칸 보이게 /

## 노드 맵·보상 화면의 목업 (`mock-party-compare.png`) — A안 채택 (2026-10-03, "노드 맵·보상은 A안으로 구현. 나머지는 대기")

사용자 지시 "노드 맵·보상 화면은 별도 목업 제공". `mock_party_panel.py`가 그렸다(오른쪽의 맵·노드 패널·보상 카드·버튼은 게임처럼 도형이다). 호출 없음.

| 안 | 내용 |
|---|---|
| 지금 | 파티 아래에 세로 칸(앞으로·뒤로 버튼은 명패 아래), 오른쪽에 맵과 노드 패널(또는 보상 카드와 버튼), 인벤토리는 오른쪽을 덮는 팝업 |
| **A안 (권장)** | 전투와 같은 하단 패널(756, 높이 324). 왼쪽 절반은 파티의 줄(얼굴, 가로 칸, 등급 배지, 고른 칸은 놋쇠색), 오른쪽 절반은 그 화면의 것: 노드 맵은 노드 제목·안내·고른 아이템의 설명·버튼("인벤토리로", "인벤토리 보기", "전투 시작"), 보상은 안내·설명·버튼("인벤토리에 넣기", "인벤토리로", "인벤토리 보기", "넘기기"). 무대(그림, 명패, 앞으로·뒤로)는 전투와 같은 자리(262). 맵은 110~740, 보상 카드는 위에 그대로. 인벤토리는 팝업 그대로(패널 위의 오른쪽을 덮는다) |
| B안 (노드 맵만) | A안에 더해 패널의 오른쪽 절반에 **인벤토리를 10칸으로 늘 보인다**(네 칸씩 세 줄, 아이템은 크기만큼 이어서). 팝업과 "인벤토리 보기"가 없어지고 노드 정보는 맵 아래로 내려간다(맵 110~600). 보상 화면도 같은 식이 된다 |

판정할 때 본 것: ① 세 화면의 파티가 같은 모양이 되는 것(A, B 모두) ② 인벤토리를 팝업으로 둘지(A) 패널에 늘 보일지(B. 인벤토리의 순서와 칸을 네 칸씩 접어 보이므로 2~3칸 아이템이 줄 끝에서 다음 줄로 넘어간다)
③ 맵이 작아지는 정도(A는 690 -> 630, B는 490) ④ 고른 아이템의 설명 줄이 패널의 오른쪽으로 가는 것.

구현(A안): `PartyColumnView`가 무대의 Column(그림, 명패, 앞으로·뒤로)과 패널의 줄(얼굴, 칸)을 함께 보여 준다. `ItemSlotView`는 높이가 아니라 폭(칸 수)을 받는다.
Builder: `UiPrefabSetup.PartySide.cs`(무대 262, 패널과 줄, 오른쪽 절반의 설명 줄과 "인벤토리로", 팝업은 패널 위까지), `NodeMap.cs`(맵 110~740, 노드 제목·안내·"인벤토리 보기"·"전투 시작"을 패널로),
`Reward.cs`(카드는 위에, 안내·"인벤토리에 넣기"·"인벤토리 보기"·"넘기기"를 패널로). 패널의 버튼은 전투 헤더와 같은 버튼 그림이다(권장안 세부: 목업의 도형 버튼 대신).
검증: 체인 통과(setup OK, sim OK, EditMode 616/616, PlayMode 43/43). 실제 화면은 `game/ko_04_map.png`, `game/ko_07_reward.png`, `game/ko_17_map_inventory_selected.png`.

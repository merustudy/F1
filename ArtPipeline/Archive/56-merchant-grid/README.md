# Round 56 — 상인의 격자 10×8과 포션 열 (검토 → 구현)

검토와 목업, 시뮬 뒤 사용자의 판정으로 구현했다(아래 "판정"·"구현"). 검토의 포션 변형은 저장소 밖의 임시 복사본에서만 고쳐 돌렸다. 호출 없음. 목업은 `mock_merchant_grid.py`가 오늘의 상점(`game/`, `20261010-s21`) 위에 그렸다.

## 지시

2026-10-10 사용자: "상점 칸을 10*8로 확장시키고, 가장 오른쪽 줄에는 포션을 세로로 비치(포션은 상점 방문시 최소 1개는 나오도록) / 9번째 줄은 비워두기 / 나머지들은 큰 물건부터 배치 / 위 사안 검토 후 보고".

읽은 것: 격자는 가로 10 × 세로 8. 1~8열에 물건(큰 것부터, 지금의 놓는 차례 그대로), 9열은 빈 칸, 10열에 포션을 위에서부터 세로로. 포션은 상점마다 적어도 하나.

## 지금(21단계)과 바뀌는 것

- 지금: 10×5 한 격자에 물건 8개(포션도 그 8개 안에서 **확률**로, 빈 포션 칸이 있을 때만 후보), 넓은 것부터 놓고 포션은 맨 끝.
- 바뀜: 포션이 물건 8개와 **따로** 뽑혀 10열에 선다 → 1~8열의 8개는 아이템·가방만이다(조금 강해짐). 포션은 두 가지뿐이라(치유·방벽, 값 8) 열에는 1~2개가 선다.
- 창: 격자가 8줄이 되어 창이 지금보다 높아진다(566 → 620, 지도 판 734 안). 1~8열(64칸)에 물건 8개라 절반 넘게 빈다.

## 시뮬 (시드 1, balanced 3,000회, 기본 파티)

| 포션의 규칙 | 클리어 / 사망 | 보스전 | 원정당 산 것 |
|---|---|---|---|
| 지금(물건 8개 안에서 확률, 빈 포션 칸이 있을 때만) | 63.8% / 0.32 | 91.3% | 2.08 |
| **A (권장)**: 따로, 종류마다 50%로 나오고 하나도 없으면 가중치(6:4)로 하나 → 1~2개 | **64.1% / 0.32** | **91.9%** | 2.27 |
| B: 따로, 늘 종류마다 하나 → 2개 | 64.9% / 0.30 | 92.4% | 2.48 |
| C: 따로, 늘 가중치로 하나 → 1개 | 63.9% / 0.32 | 91.8% | 2.21 |

- 목표 띠(Design/08 §12: 클리어 60~70%, 보스전 85~92%) 안은 지금·A·C다. B는 보스전이 위 끝을 넘는다.
- 세 변형 모두 빈 포션 칸이 없어도 포션이 나오게 돌렸다(시뮬의 손은 빈 칸이 없으면 사지 않는다).

## 목업 (`mock-merchant-grid.png`)

지금(10×5) / 안 — 포션 1개 / 같은 안 — 포션 2개. 물건 여덟은 오늘 실행의 것을 큰 것부터 1~8열에, 9열은 비우고, 10열 위에서부터 포션. 10열 위에 작은 글 "포션".

## 구현

- 데이터: `BalanceData.csv`의 `ShopPotionChancePercent` 50(새 키, 0~100), Generated. Test 데이터 둘에도.
- Domain(`ExpeditionRules`): `DrawPotions`(종류마다 확률, 없으면 가중치로 하나, 빈 포션 칸과 상관없이) — 상점 스트림에서 물건보다 먼저 뽑는다. `DrawOffers`는 아이템·가방만. 재고는 물건 다음 포션.
  `ShopGoodsCount`(데이터만으로 정함), `RefreshShop`은 물건 자리만 새로 채우고 포션 자리는 둔다. 저장 형식 그대로(검사: 물건이 `ShopSlots` + 포션 종류 수보다 많지 않음). `ExpeditionManager.ShopGoodsCount`.
- 화면: `MerchantGridView` 10×8(`GoodsColumns` 8, `PotionColumn` 9), `MerchantLayout.Lay`(물건은 1~8열에 큰 것부터, 포션은 10열에 포션 사이의 차례대로 — 산 포션의 칸은 빈다), 노드 맵은 포션의 줄을 재고의 자리에서 셈. 창은 620 높이(Builder가 격자에서 셈).
- 문서: Design/03 §5(【확정】 Round 56), 07(키), 08 §20, Architecture/07·08·12.
- Test: EditMode `MerchantLayoutTests`(포션 열), `ShopRulesTests`(물건 다음 포션, 빈 포션 칸이 없어도 나옴, 새로고침은 포션을 둠, 확률 0·100에서 늘 하나), `ShopFlowTests`(물건 다음 포션). PlayMode 상점 Test(10×8, 물건은 1~8열, 포션은 10열 위에서부터).
- 시뮬(08 §20): balanced 64.1% / 0.32, 보스전 91.5%, safe 57.4%, 여섯 파티 66.3 · 58.8 · 50.2 · 32.7 · 6.7 · 0.0 — 띠 안.

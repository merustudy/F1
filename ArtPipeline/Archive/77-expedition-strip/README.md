# Round 77 — 원정 화면의 아래 띠를 없앨까 (2026-10-17 사용자 "원정 하단에 로스터는 굳이 안보여줘도 될 것 같아(어차피 전투 던전 선택해서 출발 누르면 로스터 구성 하니) 따로 용병 리스트 버튼을 눌러 제공하는 방식으로 할까? 검토") — 판정 대기

## 지금

원정 화면(Round 71 E2 → 75 B → 76 D)은 지도·던전 정보·**아래 띠**(파티 칸 넷, 4열 → 1열, 읽기만)·[출발]이다. [출발]은 파티 팝업(무대 + 목록)을 열고, 팝업의 [출발]이 떠난다. 띠는 팝업이 생기기 전(E2: 파티는 막사에서 꾸림)의 "여기서는 보기만"의 흔적이다.

## 검토

- 띠가 주는 것: 던전을 고르는 동안 누가 가는지·피로를 한눈에. 그러나 떠나려면 반드시 팝업을 지나고, 팝업이 더 크게(그림·패시브·고통) 보여 준다. 띠의 정보는 **중복**이다.
- 띠가 가리는 것: 지도 그림의 아래 4분의 1(성문·다리·마을 밑). 띠가 없으면 지도가 온전히 보인다.
- 남겨야 하는 것: 안내 줄(출발할 수 있습니다 / 파티 부족 / 잠김 / 최종 결전)과 [출발]. 정보 패널을 아래까지 늘려 그 밑에 둔다.
- 사용자의 "용병 리스트 버튼": 여는 창은 같은 파티 팝업(무대 + 목록)이다. 버튼이 둘(편성·출발)이면 "출발 전에 파티를 보고 고치는 길"이 분명해진다. 이름은 여는 창이 파티 팝업이라 **[파티 편성]**을 권장한다("용병 목록"은 막사의 로스터와 헷갈린다).

## 안 둘 (`mock-strip-compare.png`, 지금과 나란히)

| 안 | 모습 | 장단 |
|---|---|---|
| **1 (권장)** | 띠 없음. 정보 패널이 아래(1040)까지 내려오고 그 밑에 안내 줄 "파티 4명 · 출발할 수 있습니다"와 **[파티 편성] [출발]** | 지도가 온전하고 화면이 단순하다. 파티는 숫자 하나(몇 명)로만 보이고, 자세한 것은 팝업 |
| 2 | 띠 없음. 정보 패널 밑에 파티 **한 줄**("1열 로언 · 2열 카이 · 3열 엘라 · 4열 미라", "피로 최대 0/200 · 고통 없음")과 두 버튼 | 열·이름·피로가 글로 남는다. 글이 빽빽하고 팝업과 또 겹친다 |
| 그대로 | 띠 유지 | 바꿀 것 없음. 지도를 가리고 정보가 중복 |

결정 셋(권장을 앞에):
1. 띠: **없앤다(안 1)** / 한 줄(안 2) / 그대로.
2. [출발]의 동작: **지금처럼 팝업을 연다**(팝업이 출발 확인을 겸한다. 원정 뒤 지친 용병을 보고 떠난다) / 파티가 갖춰졌으면 바로 떠나고 모자랄 때만 팝업(한 번 덜 누른다. 직접 플레이 뒤 다시 볼 만하다).
3. 버튼 이름: **[파티 편성]** / [용병 목록].

## 구현 (판정 뒤, 안 1이면)

- 빌더: 아래 띠(`Frame/Bottom`)와 `ExpeditionPartyCardView` 넷을 지우고, 정보 패널(`Frame/Details`)을 120~1040으로 늘려 밑에 안내 줄(`Status`, 파티 수를 앞에)과 [파티 편성](`Form`)·[출발](`Depart`)을 둔다. 둘 다 팝업을 연다.
- 화면: `RefreshParty`(띠)를 지우고, 안내 줄에 "파티 N명 · "를 앞세운다(문구 `Expedition.PartyCount` "파티 {0}명"). `Expedition.Party`(띠 머리글)는 지운다.
- Test: 원정 Test의 띠 단정(카드 넷, 머리글, 순서)을 패널의 안내 줄·버튼 단정으로, `UiTestUtil.DepartFromExpedition`은 그대로(`Frame/Details/Depart` → 팝업 → `PartyDepart`), 스크린샷 `_56`. 문서: Architecture/12 "원정 화면", Design/04 §7, Roadmap.

# Round 45 — 몬스터의 전리품 (보상 화면 대신 적의 아이템이 떨어진다)

검토와 권장안, 그리고 구현의 기록이다. 호출 없음(그림은 지금 아이콘 그대로). 16단계(맞추기)의 직접 플레이에 앞서 사용자가 더한 검토 항목이고,
사용자의 "검토 및 권장안대로 구현"으로 **18단계**를 열어 구현했다(아래 "판정·구현").

## 지시

2026-10-07 사용자: "몬스터 아이템도 우리 장비 및 아이템 스타일로 분류. 몬스터와 전투 후 보상 화면 대신 여러 아이템 중 그들의 아이템 중 일부 아이템 드랍(캐릭터 장착 가능),
지역 코인 일부 드랍 되게 변경 검토 및 권장안대로 구현. 유사 유명 게임 검토 후 우리 게임 변경 검토."

읽은 것(해석. 틀리면 사후 검토에서 고친다):

- "우리 장비 및 아이템 스타일로 분류" = 적의 아이템도 용병의 것처럼 **들 수 있는 물건**(무기 장비·방어 장비·공격 아이템·지원 아이템·기타)이어야 한다.
  지금 적의 아이템 일곱 가운데 "물어뜯기", "치유 주문", "감독관의 포효"는 물건이 아니라 **행동**의 이름이다. 떨어져서 용병이 들면 어색하다.
- "보상 화면 대신 … 그들의 아이템 중 일부 드랍" = 던전 공통 후보 셋 중 하나를 고르는 **보상 선택을 없애고**, 쓰러뜨린 적이 **들고 있던 아이템** 가운데 몇 개가 떨어진다. 떨어진 것은 용병이 든다.
- "지역 코인 일부 드랍" = 코인도 전리품이다. 지금의 "이긴 전투의 코인"(17단계)을 그대로 전리품의 한 줄로 둔다.

## 지금

- 보스가 아닌 전투에서 이기면 **보상 화면**: 던전 공통 후보(보상 가중치가 있는 아이템 여덟과 포션 둘)에서 셋을 뽑아 하나를 고르거나 넘긴다. 등급은 던전의 값(8), 단계는 층(동 5층, 은 10층, 정예 +1).
- 적의 아이템은 `EnemyData.Items`(아이템과 등급)로 적의 보드에 서고, 전투가 끝나면 사라진다. 적의 아이템 일곱: 물어뜯기(쥐), 녹슨 칼·조잡한 활·등불 지팡이·치유 주문(고블린), 감독관의 망치·감독관의 포효(보스). 정예 고참은 버클러(용병의 것)도 든다.
- 코인은 이긴 전투에서 적마다 1 + 층마다 1(정예 배). 결과 창의 "지역 코인 +N".

읽은 것:

1. "쓰러뜨린 적의 것이 떨어진다"에 가장 가까운 것은 **The Bazaar**(몬스터 자신의 아이템 하나가 전리품)와 **Diablo**(몬스터의 표)다. 우리 적의 보드는 이미 아이템의 목록이라 따로 표를 두지 않고 그대로 뽑을 수 있다.
2. "일부"의 수: The Bazaar 하나, Slay the Spire 하나(+포션), Darkest Dungeon은 무리마다 여럿. 우리는 데이터(`DropCount`, 정예는 `EliteDropCount`)로 두고 시뮬로 정한다.
3. 자리가 없을 때: Darkest Dungeon·Diablo는 **두고 간다**, Loop Hero는 자동 변환. 우리는 보드와 인벤토리(10칸)가 있고 "버리는 명령이 없다"(개정 4)는 규칙이 있으니 **집거나 두고 가기**가 맞다. 지금의 "넘기기"가 "두고 가기"가 된다.
4. 코인은 레퍼런스 모두 자동이다(The Bazaar·Slay the Spire·TFT). 지금처럼 전투가 끝나는 순간 더하고 결과 창에 적는다.
5. 포션은 Slay the Spire만 전투 뒤에 준다. 우리 적은 포션을 들지 않으므로 전투에서 포션이 나오지 않게 되고, 시작 포션과 상점(17단계)만 남는다. 클리어율이 띠 밖으로 가는지 시뮬로 본다.

## 우리 게임에 적용 — 안

### 1. 적 아이템의 이름과 분류

| id | 지금 | 안 | 분류 |
|---|---|---|---|
| `rat_bite` | 물어뜯기 / Bite | **쥐 송곳니 / Rat Fang** | 무기 장비(그대로) |
| `mending_chant` | 치유 주문 / Mending Chant | **치유의 부적 / Mending Charm** | 지원 아이템(그대로) |
| `overseer_roar` | 감독관의 포효 / Overseer's Roar | 그대로 — 보스의 것은 떨어지지 않는다(보스를 이기면 원정이 끝난다). 바꾸려면 새 이름과 새 그림이 필요하다 | 무기 장비(그대로) |
| 녹슨 칼, 조잡한 활, 등불 지팡이, 감독관의 망치, 버클러 | 이미 물건 | 그대로 | 그대로 |

- 아이콘은 그대로 맞는다: `rat_bite`는 쥐의 앞니 둘, `mending_chant`는 뼈와 잎을 끈으로 묶은 부적이다. 호출 없음. id는 그대로 둔다(그림 주소와 Test가 id에 묶여 있고, 저장 파일에 들어간다).
- 수치(쿨다운, 자리, 효과)는 그대로다. 전투는 바뀌지 않는다.

### 2. 전리품의 규칙

- 보스가 아닌 전투에서 이기면 **보상 선택이 없다**. 대신 쓰러뜨린 적들이 들었던 아이템을 모두 모아 그 가운데 `DropCount`개(정예는 `EliteDropCount`개)를 **전리품 난수**로 겹치지 않게 뽑는다. 적의 아이템이 그보다 적으면 모두 떨어진다.
  같은 아이템이 여럿이면(쥐 넷의 송곳니 넷) 같은 것이 여럿 떨어질 수 있다 — 합치기의 재료다.
- 떨어진 아이템은 **그 적이 들었던 등급 그대로**(깊은 층의 보정 포함), 단계는 **일반**이다(적의 아이템은 일반). "녹슨 칼 · 등급 15"를 든 약탈자를 쓰러뜨리면 그 녹슨 칼이 떨어진다.
  - 대안 (2): 층의 단계(동 5층, 은 10층, 정예 +1)와 던전의 보상 등급(8)로 떨어진다 — 지금 보상의 힘 곡선 그대로이지만 전투에서 본 것과 다른 등급이 떨어진다. 시뮬로 둘을 재고 고른다(아래 "시뮬").
- 보상 후보(`RewardChoices`)와 보상 가중치는 없어진다. 가중치는 상점의 것(`ShopWeight`)으로 이름을 바꿔 남는다. 던전 공통 아이템(단검·장궁·창·미늘창·버클러·수호 부적·약초 주머니·불씨 플라스크)과 포션은 **상점에서만** 산다.
- 코인은 그대로(적마다 `CoinsPerEnemy` + 층마다 `CoinsPerFloor`, 정예 `EliteCoinPercent`). 수치는 시뮬로 다시 본다(포션이 상점에서만 나오므로).
- 난수: 원정 시드에서 파생한 전리품 스트림 `Derive(원정 시드, "loot", 노드 id)`(보상 스트림을 대신한다). 같은 시드와 같은 길이면 같은 전리품이다.

### 3. 전리품 화면 (보상 화면을 고쳐 쓴다)

- 같은 자리, 같은 틀이다: 파티 쪽(왼쪽)과 오른쪽의 카드. 제목은 "전리품", 카드는 떨어진 아이템마다 하나(최대 3: 카드 셋이 들어가는 자리). 카드의 동작은 "줍기".
- 카드를 누르면 고르고(놋쇠 테), 왼쪽 보드의 칸을 누르면 거기에 든다(찬 칸이면 밀어내기, 같은 아이템 위면 합치기 — 보상·상점과 같다). "인벤토리에 넣기"로 바로 받을 수도 있다.
  하나를 주우면 그 카드는 "주움"으로 남고 다음 것을 계속 주울 수 있다. 모두 주우면 화면이 닫히고, "두고 가기"는 남은 것을 버리고 다음 층으로 간다.
- 전투 결과 창에 "전리품: 녹슨 칼 · 등급 15, 쥐 송곳니 · 등급 10" 줄이 "지역 코인 +N" 위에 선다 — 쓰러뜨린 순간에 무엇이 떨어졌는지 보인다.
- 카드의 모양은 그대로(글 카드). 아이콘을 넣은 카드는 【검토】로 두고 목업 라운드에서 본다.

### 4. 시뮬과 저장

- 시뮬 정책: 떨어진 것마다 합쳐지면 줍고, 자리가 맞는 구성원의 빈 칸에 줍고, 인벤토리에 자리가 있으면 줍고, 아니면 둔다. 보고에 떨어진 수·주운 수를 더한다.
- 저장 9: 전리품 목록 `Loot`(주운 자리는 null)이 보상 후보 `PendingRewards`를 대신한다. 8의 보상을 고르던 파일은 노드 고르기로 돌아온다(그 보상 하나는 잃는다. 지금 사용자의 저장 파일은 원정 중이 아니다).

## 권장

1. 이름 둘(쥐 송곳니, 치유의 부적)을 바꾸고 포효는 그대로 둔다. 분류는 모두 그대로.
2. 전리품: 적의 아이템에서 `DropCount`개(정예 `EliteDropCount`개), **그 적이 들었던 등급 그대로·일반**. 수는 시뮬로.
3. 화면: 보상 화면을 전리품 화면으로(제목·"줍기"·"주움"·"두고 가기"). 결과 창에 전리품 줄.
4. 포션은 시작 포션과 상점에서만. 띠 밖이면 코인 수입이나 포션 값이 레버다.
5. 범위: **18단계 "몬스터의 전리품"**을 Slice B에 더한다. 16단계의 맞추기는 이 데이터로 한다.

## 판정할 것

1. 이름: 쥐 송곳니 / 치유의 부적 / 포효 그대로.
2. 전리품의 등급과 단계: (1) 그 적의 것 그대로·일반(권장) / (2) 층의 단계와 던전의 등급.
3. 수: `DropCount`·`EliteDropCount`(시뮬로).
4. 화면: 글 카드 그대로(권장) / 아이콘 카드(목업 라운드).
5. 포션은 상점에서만(권장) / 적이 포션도 떨어뜨림(데이터 열 하나 더).

## 판정 (2026-10-07)

사용자: **"검토 및 권장안대로 구현"**(지시에 미리 담겨 있었다. 사용자는 구현 동안 세션에 없었다: 아래는 모두 사후 검토 대상) → 판정할 것 다섯을 권장안으로 정하고 **18단계**를 열었다(Roadmap "18단계의 승인").

1. 이름: 쥐 송곳니, 치유의 부적. 포효는 그대로.
2. 등급과 단계: **시뮬이 (1)을 거부했다**(클리어 100%). (2) 층의 단계·던전의 등급도 드랍 하나에 81%였다 — 적의 아이템의 계수가 우리 아이템보다 높아서. 그래서 **적의 아이템을 우리 척도로 다시 적고**(계수 송곳니 60·녹슨 칼 80·등불 25, 등급을 올려 전투의 수치는 그대로) (2)로 떨어뜨린다. 사용자의 "우리 장비 및 아이템 스타일로 분류"를 이름뿐 아니라 척도까지로 읽은 것이다.
3. 수: 드랍 1, 정예 2(둘씩이면 96%).
4. 화면: 글 카드 그대로. 아이콘 카드는 【검토】.
5. 포션: 상점에서만(값 6도 수치가 같았다).

## 구현 (18단계)

- 규칙·데이터·저장·Application·시뮬·화면·Test는 Roadmap 18단계와 Architecture/07·08·11·12, Handoff `Docs/Workstreams/active/b18-loot.md`에. 시뮬은 Design/08 §14.
- 안에서 바뀐 것(권장안으로 정했고 Roadmap "사후 검토 대기"에 올렸다):
  - §2의 "그 적이 들었던 등급 그대로·일반"은 **버렸다**(시뮬 100%). 대안 (2)에 **적 아이템의 척도 변경**을 더했다.
  - 처치의 피로 완화 `FatigueOnKill`을 5에서 3으로: 보드가 세져 처치가 늘고 붕괴가 10%로 내려가서. 16단계의 J(피격 2·처치 5)는 피격 2·처치 3이 됐다.
  - 보상 후보의 코드 이름(`RewardOption`·`RewardKind`·`ChoosingReward`·`PendingRewards`·`RewardWeight`·`RewardChoices`·`Reward` 화면과 문구)을 모두 전리품·상점의 이름으로 바꿨다(`ItemOffer`·`OfferKind`·`PickingLoot`·`Loot`·`ShopWeight`·`DropCount`·`LootScreen`·`Loot.*`). 저장은 9.
  - 주운 카드는 **그 자리에 남는다**(어두운 판, "주움"): 자리가 밀리지 않고 무엇을 주웠는지 보인다. 상점의 "팔림"과 같은 모양.
- 목업은 만들지 않았다: 화면의 틀(카드 셋, 버튼 줄)이 보상 화면 그대로이고 글만 바뀐다. 구현 장면은 아래 "게임의 모습".

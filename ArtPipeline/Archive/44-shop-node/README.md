# Round 44 — 상점 노드와 지역 코인

목업이다. 호출 없음. 16단계(맞추기)의 직접 플레이에 앞서 사용자가 더한 검토 항목이다.
상점과 재화는 Architecture/09의 **Deferred**(경제: 재화·고용·상점, 다른 노드 종류)에 있으므로 "어느 단계에서 하는가"의 결정이 함께 필요하다(아래 §6).

## 지시

2026-10-07 사용자: "전투 선택지에서 상점 신설 검토 — 전투 전용 재화: 지역 코인(런-전투에만 누적, 전투 끝나면 초기화) / 아이템 형태 보여주고 설명은 툴팁으로 마우스 우클릭 시 제공 /
일정 금액 지불시 다시(리프래쉬) 기능(누적 증가, 상점 나가면 초기화). 관련 유사 유명게임 검토 후 우리 게임에 어떻게 적용할 지 목업 제공".

읽은 것(해석. 틀리면 판정에서 고친다):

- "전투 선택지" = 노드 맵에서 고르는 노드의 종류. 전투·정예·야영지·보스에 **상점**을 더한다.
- "런-전투" = 11단계에서 정한 **전투 런 = 원정 하나**. 그래서 지역 코인은 **원정 안에서만** 쌓이고 쓰이며, 원정이 끝나면(클리어·전멸·후퇴) 아이템처럼 사라진다. 로비의 재화(Slice C)와는 다른 것이다.
- "아이템 형태" = 보드의 칸에 보이는 그 모양(아이콘). 보상 화면의 글 카드가 아니다.

## 지금

- 노드 종류는 넷(전투·정예·야영지·보스. Design/03 §1). 상점·이벤트·보물은 Slice C 이후다. 재화는 어디에도 없다(로비의 재화·고용·상점도 Slice C: Design/04 §5).
- 원정 안에서 아이템을 얻는 길은 셋이다: 전투 뒤의 보상(셋 중 하나), 합치기, 야영지의 정비.

## 우리 게임에 적용 — 안

### 1. 지역 코인 (`mock-coins.png`)

- `ExpeditionState`의 정수 하나. **전투에서 이기면** 받는다: 적 하나마다 `CoinsPerEnemy` + 층마다 `CoinsPerFloor`, 정예는 `EliteCoinPercent`배, 보스는 없음(끝이므로). 수는 데이터(`BalanceData`)이고 시뮬로 정한다.
- 원정이 끝나면 **귀환 정산 1**(아이템과 포션이 사라진다)에 함께 사라진다. 런·로비에는 없다. 이어하기는 `run.json`의 원정 부분에 담긴다.
- 보이는 곳: 모든 원정 화면의 **헤더**(층 수 옆, 코인 표식 + 수), **전투 결과 창**("지역 코인 +N"), 상점 창("가진 코인").
- 이름은 "지역 코인"(기획 용어). 지역마다 이름과 그림을 달리하는 것은 나머지 지역과 함께 Slice C다. 코인의 그림은 도형(놋쇠 원)으로 시작한다.

### 2. 상점 노드 (`mock-node.png`, `mock-marker.png`)

- 노드 종류 다섯째. 정예·야영지와 같은 방식으로 던전 데이터가 층과 확률을 갖는다(`ShopMinFloor`, `ShopChancePercent`). 1층, 야영지 층(15), 그 바로 앞 층에는 없다(쉬는 곳이 잇달아 나오지 않게 하는 야영지의 규칙과 같이).
  정예 → 야영지 → 상점의 차례로 노드마다 맵 난수로 정한다(같은 시드 = 같은 맵).
- 노드를 고르면 패널은 "N층 · 상점", "지역 코인으로 아이템을 사는 곳입니다. 싸움은 없습니다.", 버튼 "상점으로". 들어가면 피로는 오르지 않는다(야영지와 같다).
- 표식 세 안(도형. 그림은 지시가 있을 때 생성): **A 코인 더미(권장. 코인 표식과 같은 말)**, B 천막(좌판), C 저울.

### 3. 상점 창 (`mock-window-compare.png`)

| 안 | 모양 |
|---|---|
| 지금 | 야영지의 창: 지도 위 580x320, 카드 둘 |
| **A (권장)** | 야영지와 같은 **지도 위의 창**, 820x360. 물건 넷을 **보드 칸의 모양**(아이콘, 단계의 외곽선·별)으로, 밑에 이름·분류·칸 수·값. 오른쪽 위에 "가진 코인". 아래에 [새로고침 · N코인] [나가기] |
| B | 보상 화면처럼 **따로 화면**: 글 카드 셋(제목·사실·효과), 값은 "고르기" 자리. 새로고침·나가기는 패널의 버튼 줄 |
| C | A의 창에 물건 **셋**, 타일마다 사실까지 적어 카드가 필요 없게 |

- A: 사용자의 "아이템 형태"다. 야영지와 같은 틀(같은 화면, 같은 그늘, 같은 놋쇠 테)이라 새 화면 조각이 가장 적다. 사실은 카드(§4)가 말한다.
- B: 사실이 다 보이지만 아이콘이 없고(보상 카드처럼 글), 새 화면(`ShopScreen`)과 그 Prefab·Test가 는다.
- C: 카드가 없어도 되지만 물건이 셋으로 줄고 글이 15px라 작다.

### 4. 사기 (`mock-buy-flow.png`)

| 안 | 동작 |
|---|---|
| ㄱ (사용자안) | **우클릭** = 카드만(고르지 않음). **좌클릭** = 바로 사서 **인벤토리로**(자리가 없으면 눌리지 않음). 보드에 놓는 것은 인벤토리에서 지금처럼 |
| **ㄴ (권장)** | **좌클릭** = 고르기(놋쇠 테) + 카드(Round 42 규칙 그대로. 창 아래에 뜨고 위 꼭지가 타일을 가리킨다) + 왼쪽 보드의 칸이 기다린다. **칸을 누르면 그때 코인이 나가고** 들어간다(찬 칸이면 밀어내기, 같은 아이템이면 합치기 — 보상과 같다). 패널의 [인벤토리에 넣기]로 바로 받을 수도 있다 |

- ㄴ은 보상 카드의 "고르고 → 놓기"와 같은 흐름이다. 놓을 때 사므로 잘못 눌러도 코인이 남고, 합치기가 바로 된다. 우클릭이라는 새 입력이 상점에만 생기지 않는다.
- ㄱ은 한 번에 사지만 인벤토리를 거쳐 다시 꺼내야 하고(두 걸음), 잘못 누르면 코인이 나간다. 우클릭은 Input System의 `Mouse.rightButton`으로 받을 수 있지만 터치에는 없다(PC 전용이라 막지는 않는다).
- 둘 다: 코인이 모자라면 타일의 값이 붉고 눌리지 않는다. 포션은 빈 포션 칸이 있을 때만(보상과 같다). 판 자리는 "팔림"으로 남는다.
- 사용자가 ㄱ의 우클릭을 원하면 ㄴ에 더할 수도 있다(우클릭 = 고르지 않고 카드만). 권장은 ㄴ만.

### 5. 새로고침 (`mock-refresh.png`)

- 누르면 **팔리지 않은 물건을 모두** 새로 뽑는다(판 자리도 채운다). 비용은 **시작값 `ShopRefreshBase`에서 한 번마다 `ShopRefreshStep`씩** 오르고(그림은 3, +2), **상점을 나가면 초기화**된다(다음 상점은 다시 시작값). Balatro·Brotato의 모양.
- 코인이 모자라면 버튼이 꺼지고 값이 붉다.
- 물건을 뽑는 난수는 원정 시드에서 파생한 **상점 스트림**(Design/09 §5의 스트림 목록에 하나 더)이라 같은 시드면 같은 물건이 나오고, 새로고침의 횟수도 저장된다(이어하기).
- 대안: (b) 층에 비례한 시작값(Brotato식) — 코인도 층에 비례해 느니 굳이 필요 없다. (c) 처음 몇 번은 싸게(Backpack Battles식) — 수가 셋이 된다. 권장은 위의 둘.

### 6. 범위 — 어느 단계에서

| 안 | 내용 |
|---|---|
| **(가) 권장: 17단계로, 16단계 뒤에** | 16단계(맞추기: 사용자의 직접 플레이 → 맞추기와 마감)를 먼저 끝내고 Slice B 완료를 보고한 뒤, **17단계 "상점 노드와 지역 코인"**을 Slice B에 더해 한다(Architecture/09 Slice B의 범위 표와 Design/03 §1을 그때 고친다). 원정의 길이와 긴장의 곡선(15~30분)을 바꾸는 것이므로 "전투 시스템 완성"의 일이다. 로비의 재화·고용(Slice C)은 그대로 미룬다 |
| (나) Slice C의 첫 단계로 | Slice B를 지금 범위로 닫고, 상점은 경제(재화·고용)와 함께 Slice C에서. 로비 재화와 한 번에 설계할 수 있지만, 원정의 맞추기를 두 번 하게 된다 |
| (다) 16단계 안에서 함께 | 맞추기의 수치가 상점 때문에 흔들려 두 가지를 한 번에 재게 된다. 권장하지 않는다 |

- 어느 쪽이든 **지금 세션의 다음 걸음은 사용자의 직접 플레이**(x1로 원정 하나)다. 그 기록 없이는 16단계의 맞추기와 마감을 할 수 없다.

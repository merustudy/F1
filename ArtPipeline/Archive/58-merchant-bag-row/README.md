# Round 58 — 상인의 가방 줄 (바로 구현)

목업 없이 바로 구현했다(사용자 지시). 데이터·Domain·저장은 그대로이고 화면의 자리만 바뀌었다. 호출 없음.

## 지시

2026-10-10 사용자: "가방도 포션처럼 특정 위치에 비치(맨 아래줄은 가방 전용), 아래서 +1줄은 비우기. 해당 규칙 적용해 바로 구현해줘".

읽은 것: 10×8 격자의 **8행(맨 아래)은 가방 전용**, **7행은 빈 줄**. 아이템은 그 위(1~6행). 9열 빔·10열 포션(Round 56)은 그대로.

## 빈 곳을 권장안으로 (사후 검토)

| # | 정한 것 | 이유 |
|---|---|---|
| 1 | 가방은 8행의 **1~8열** 안에만 놓는다(9·10열로 넘어가지 않음) | 9열 빔·10열 포션의 규칙을 지킴. 파는 가방은 둘(2×1·3×1, 5칸)이라 한 줄에 든다 |
| 2 | 가방의 차례는 **넓은 것부터, 왼쪽부터**(같으면 재고의 앞 것부터) | 물건의 "큰 것부터"와 같은 규칙 |
| 3 | 아이템이 6행을 넘으면 행을 더하고 **빈 줄과 가방 줄도 함께 내려간다**. 가방이 한 줄에 다 들지 않으면 그 아래 줄로 | 지금 데이터에서는 일어나지 않음(아이템 8개는 늘 8×4 안). 그래도 겹치지 않게 |
| 4 | 산 가방의 자리는 새로고침까지 빈다 | 지금의 규칙 그대로(자리는 재고마다 기억) |

## 구현

- `MerchantLayout.Lay(goods, width, itemRows, bagRow, potionColumn, out rows)`: 아이템은 위에서부터, 가방은 `bagRow`(아이템이 넘친 만큼 아래로)에서부터, 둘 다 같은 놓기(`Pack`). `MerchantGood`는 `OfferKind`를 가진다(포션 여부 대신).
- `MerchantGridView.BagRow`(= 8행) · `ItemRows`(= 6행). `NodeMapScreen`이 재고의 종류를 넘긴다.
- Test: EditMode `MerchantLayoutTests` 넷(가방이 맨 아래 줄에 넓은 것부터, 아이템이 넘치면 가방 줄도 내려감, 같은 물건은 같은 자리). PlayMode 상점 Test(가방은 8행, 아이템은 6행 안).
- 문서: Design/03 §5(【확정】 Round 58), Architecture/12 "상점 — 상인".

# Round 74 — 상점에서 아이템 팔기 (2026-10-17 사용자 "상점 아이템 판매 기능 추가")

같은 턴의 "전리품 드랍된 남은 것을 단축키를 눌러 바로 인벤에 넣기 신설 추가"는 작고 뜻이 분명해 바로 구현했다(아래 "전리품의 A 키"). 팔기는 규칙과 파는 자리를 정해야 해서 목업으로 판정을 받는다(사용자 규칙: 배치는 구현 전에 목업으로).

## 지금

상점 창(17단계, Round 44·56·58)은 사기·새로고침·나가기뿐이다. 코인은 전투에서만 들어온다(03 §5). 아이템을 버리는 명령도 없다(전리품은 두고 가고, 보드·인벤토리의 것은 둔다).

## 규칙 (권장안)

- **값**: 파는 값 = 그 아이템을 상점에서 살 값(`Price` × 단계의 `Tier*Percent` / 100)의 **`SellPercent`(출발값 50 → 2026-10-18 사용자 플레이 피드백 "상점 판매가 현재의 1/2로"로 25)%**, 적어도 1. 코인은 `ExpeditionState.Coins`에 더하고, 판 아이템은 사라진다(상점의 물건이 되지 않는다).
- **팔 수 있는 것**: 보드와 인벤토리의 아이템. **기본 무기**(`IsBase`: 용병이 빈손이 되지 않게), **유니크**(글라디우스), **가방**(안의 것과 함께 다뤄야 함 — 다음), **포션**(포션 칸의 것)은 팔 수 없다.
- **값이 0인 아이템**: 적이 떨어뜨리는 아이템(녹슨 칼·조잡한 활·등불 지팡이·치유의 노래·감독관의 망치·포효·쥐 송곳니·심연의 셋)은 `Price`가 0이라 지금은 상점에 나오지 않고 팔 값도 없다. `ShopWeight`가 0이면 값이 있어도 상점에 나오지 않으므로, **이들에 `Price`를 준다**(권장 출발값: 쥐 송곳니 2, 녹슨 칼·조잡한 활 6, 등불 지팡이·치유의 노래 8, 감독관의 포효 12, 망치 14, 심연의 울부짖음·손아귀 12, 식칼 16). 숫돌은 값 1(임시)이라 1에 팔린다.
- 시뮬의 정책은 팔지 않는다(코인이 남아 새로고침에 쓰이는 지금과 같다). 팔기가 원정의 승률을 바꾸지는 않는다 — 상점의 물건을 더 사게 할 뿐.

## 파는 자리 — 안 셋 (`mock-sell-compare.png`, 지금 창 위에)

| 안 | 모습 | 손 | 장단 |
|---|---|---|---|
| **A (권장)** 상인의 접시 | 새로고침과 나가기 사이에 놋쇠 테의 접시. "팔기 · 아이템을 든 채로 여기에 놓으세요 · 값의 절반". 든 동안 금테가 되고 이름과 값을 보인다. 팔 수 없는 것을 들면 붉은 글("기본 무기는 팔 수 없습니다") | 지금의 손 그대로: 보드·인벤토리의 아이템을 집어(좌클릭) 접시에 놓는다(좌클릭). 사기의 "고르고 → 놓기"와 같은 결 | 새 입력도 새 모드도 없다. 잘못 누를 길이 없다(접시에 놓아야 팔린다). 창 안이라 상점에서만 보인다 |
| B 카드의 버튼 | 아이템 카드(우클릭)에 "팔기 ◉ 6" 버튼이 상점에서만 붙는다 | 우클릭 → 버튼 | 두 걸음. 카드는 "보는 것"이었는데 명령이 생긴다(Round 47의 규칙이 흐려짐) |
| C 팔기 토글 | 새로고침 옆의 "팔기" 토글. 켜면 모든 아이템 칸에 값이 뜨고 누르면 팔린다 | 토글 → 칸 클릭 | 한 번에 여럿 팔기 쉽다. 그러나 켠 것을 잊고 누르면 팔린다(모드의 함정). 칸 위의 값 글이 보드를 어지럽힌다 |

권장은 **A**다. 손의 규칙이 그대로이고, 판 자리를 접시가 받으니 되돌릴 필요가 없다(값을 보고 놓는다).

## 구현 (판정 뒤)

- Domain: `ExpeditionRules.SellPriceOf(data, EquippedItem)`, `CanSellFromBoard/Inventory`, `SellFromBoard(구성원, X, Y)`, `SellFromInventory(index)`(AtShop에서만). `BalanceData` `SellPercent`. `ItemData.csv`의 값들.
- Flow: `ExpeditionManager`의 명령 둘(끝에서 저장). Save는 바뀌지 않는다(코인·아이템은 이미 저장).
- UI: 상점 창의 접시(`ShopTray`: `IOutsideHand`의 반대쪽 — 손에 든 보드·인벤토리 아이템을 받는 자리), 문구 넷. 노드 맵 화면의 `Pressed` 차례에 접시를 더한다(12_UI "누름의 차례").
- Test: EditMode(값, 팔 수 없는 것, 코인, 사라짐, 저장 왕복), PlayMode(집어서 접시에 놓기).
- 문서: Design/03 §5(【확정】 사용자 결정 + 권장안 세부), 07 §4(값), Architecture/08·11·12.

## 전리품의 A 키 (같은 턴, 바로 구현)

전투에서 이긴 뒤 바닥의 전리품이 남았을 때 **A**를 누르면 인벤토리에 자리가 있는 것을 놓인 차례대로 모두 넣는다(각각 첫 빈 자리에). 가방과 자리가 없는 것은 바닥에 남고, 모두 넣었으면 전리품이 끝난다(마지막 것을 주울 때와 같다). 든 전리품은 먼저 놓는다. 넣을 것이 없으면 버튼 소리만. 안내문에 "A: 남은 전리품을 모두 인벤토리에"를 더했다. `TakeAllKey`(I의 `InventoryKey`와 같은 꼴), `ExpeditionRules.TakeAllLootToInventory`, `ExpeditionManager.TakeAllLootToInventory`(저장 한 번).

## 판정 (2026-10-17 사용자)

"1. 안 b / 2. 50%, 권장안 수용 / 3. 권장안으로 수용" — 파는 자리는 **B(카드의 버튼)**, 값은 살 값의 50%(적어도 1), 기본 무기·유니크·가방·포션은 못 팖, 적 아이템의 값은 위 출발값. 구현은 같은 날(Roadmap 29, Handoff `c29-tuning.md`). 카드 위의 누름이 카드를 닫지 않게 했다(버튼이 눌리게).

## 판정할 것 (판정 전의 목록)

1. 파는 자리: A / B / C.
2. 파는 값의 비율 50%와 팔 수 없는 것(기본 무기·유니크·가방·포션).
3. 적이 떨어뜨리는 아이템의 값(위 출발값).

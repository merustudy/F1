# Round 86 — 적의 보드를 기본 가방(3×3)으로 (2026-10-19) — 판정됨

판정(2026-10-19 사용자 **"권장안 구현"**): 넷 모두 권장안 — 시작 가방과 같게, 읽는 차례의 처음 자리, 폭 3 그대로 아래로 확대(8줄까지, 넘으면 데이터 검사), 붉은 돌 테. 구현은 Architecture/12 "전투의 보드".

지시: 2026-10-19 사용자 "적 몬스터들도 인벤토리 기본 공간(3*3)으로 시작 (보스 몹 등 아이템 많은 경우 자동 확대) 검토 수행".
지금: Architecture/12 "전투의 보드" — 적은 가방이 없어 아이템 조각만 데이터의 차례대로 한 줄씩 아래로, 조각마다 붉은 돌 테의 우물(`BoardLayout.Stacked`).
그림 생성 API는 부르지 않았다(스크린샷의 조각을 잘라 옮김).

## 검토

- **화면만의 일이다**: 적의 배치(`BoardLayout`)는 전투 화면만 쓴다. 엔진(피해·쿨다운·발동 차례)은 배치를 읽지 않고 적의 아이템은 데이터의 차례대로 돈다. 저장도 배치를 갖지 않는다(전투 Setup은 데이터에서 다시 만든다). 그래서 결정론·시뮬·저장은 그대로다.
- **지금의 데이터로는 확대가 필요한 적이 없다**: 아이템이 가장 많은 것은 심연의 군주(페이즈 2·3: 2×1 셋)이고 3×3에 들어간다. 주술사·주술 대가의 3×1 + 2×1, 고참·호위의 2×1 + 1×1도 들어간다. 확대는 앞으로의 보스를 위한 규칙이다.
- 영향: 적의 보드가 아군처럼 3칸 높이가 된다(지금은 아이템 줄 수만큼). 보스가 페이즈에서 아이템을 바꾸면 그 페이즈의 배치로 다시 그린다(지금처럼). 전투 스크린샷이 모두 바뀐다.

## 판정할 것 (권장)

1. 가방의 크기: **용병의 시작 가방(`BagData`의 `Start` — 가죽 배낭 3×3)과 같게**. 시작 가방이 바뀌면 적도 따른다(새 데이터 없음).
2. 놓는 법: **읽는 차례(위 → 아래, 왼쪽 → 오른쪽)로 처음 들어가는 자리**에, 데이터의 아이템 차례대로. 그래서 호위의 방패는 칼 옆에 선다. / 지금처럼 한 줄에 하나씩.
3. 확대: **폭 3은 그대로 두고 아래로 한 줄씩**(틀의 높이 8까지) 하나의 우물이 늘어난다. 8줄에도 안 들어가는 적은 데이터 검사가 막는다. / 3×1 가방을 아래에 더하는 모습(용병의 가방 더하기처럼).
4. 테의 색: **안 A 붉은 돌 테**(지금 적의 우물 색 — 적과 아군이 한눈에 갈림). / 안 B 가죽(아군과 같음).

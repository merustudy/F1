# Round 34 — 긴 원정의 지도와 야영지

목업이다. 호출 없음. Slice B 13단계에서 원정이 지도 15층 + 보스(16층)가 되고, 정예와 야영지 노드가 생긴다(Design/03 §1·§2·§5).
지금의 노드 맵은 4층(3층 + 보스)을 한 화면(태블릿 안 860x354, 층 사이 88.5)에 놓는다. 16층은 그대로는 들어가지 않는다.
Domain(정예·야영지·쉬기, 깊은 층의 적)은 이미 있고 Test를 통과했다. 게임의 데이터는 화면이 생길 때까지 지금의 3층 그대로다.

## 지시

Slice B의 권장안(2026-10-06, 사용자 "권장대로 구현"): 화면이 바뀌는 곳은 목업으로 먼저 승인받는다. 이 라운드는 13단계의 지도와 야영지다.

## 안

지도 (`mock-map-compare.png`, 10층에서 11층의 전투와 정예 중 정예를 고른 때):

| 안 | 모양 |
|---|---|
| 지금 | 4층을 한 화면에. 노드 74, 이름 18 |
| **A (권장)** | 위로 스크롤. 층 사이(88.5)·노드·이름은 지금 그대로, 한 번에 4층 남짓. 화면을 열 때와 층을 옮긴 뒤 지금 층이 아래쪽에 오도록 맞춘다. 오른쪽에 스크롤 막대 |
| B | 16층을 한 화면에, 위로. 층 사이 24, 노드 22, 이름 없음 |
| C | 16층을 한 화면에, 왼쪽에서 오른쪽으로. 층 사이 55, 노드 42, 이름 없음 |

야영지 (`mock-camp-compare.png`):

| 안 | 모양 |
|---|---|
| 공통 | 정예를 고르면 제목 "11층 · 정예", 안내 "강한 적 무리가 기다립니다.", 버튼 "전투 시작". 야영지를 고르면 "7층 · 야영지", "싸움 없이 쉬어 가는 곳입니다.", 버튼 "야영지로" |
| **A (권장)** | 들어가면 패널의 오른쪽 절반이 야영지가 된다: 제목, 안내, 쉬기·정비의 효과, 보드 도움말. 전투 시작의 자리에 [정비] [쉬기] |
| B | 지도 위의 창(지도는 어둡게)에 쉬기·정비 카드. 패널에는 보드 버튼만 |

- 정예의 표시: 전투의 칼 아이콘을 붉은 마름모 위에. 야영지: 장작 둘과 불꽃. 둘 다 스크립트로 그린 도형이다(그림 자리. 그림을 생성하려면 지시가 필요하다).
- 지나온 층의 노드는 지금처럼 어둡게(지나온 길을 따로 표시하지 않는다).
- 지도는 게임의 생성기 그대로다(`Tools/Sim map --dungeon abandoned_mine --seed 7`, 13단계 출발 데이터 → `game/map15_seed7.txt`).

## 권장: 지도 A, 야영지 A

- 지도 A: 노드·이름·간격이 승인받은 지금 모양 그대로이고, 위로 오르는 방향도 같다(Slay the Spire의 지도와 같은 방식). 고를 때 필요한 것은 다음 두세 층이고,
  더 먼 길(정예를 피할지, 야영지로 갈지)은 스크롤해서 본다. B는 노드가 22라 아이콘이 읽히지 않는다. C는 한눈에 보이지만 노드가 작아지고 이름이 빠지며 방향이 바뀐다.
- 야영지 A: 노드를 고르고 버튼을 누르는 지금의 흐름 그대로이고, 왼쪽 보드를 보면서 고를 수 있다(14단계의 정비는 보드의 아이템을 고른다). B는 창이 지도를 가리고 새 화면 조각이 는다.
- 13단계에는 쉬기만 들어간다. [정비]는 14단계에서 같은 자리에 들어온다(그 전에는 버튼이 없다).

## 판정할 것

1. 지도: 지금 / A / B / C.
2. 야영지: A / B.
3. 정예·야영지의 도형 표시를 그대로 쓸지(권장: 그대로. 그림은 지시가 있을 때 생성).

## 고르면 (구현)

- 지도 A: `UiPrefabSetup.NodeMap`의 맵 영역을 스크롤 뷰(ScrollRect, RectMask2D)로, `NodeMapScreen.BuildMap`이 층 사이 88.5로 내용의 높이를 정하고 지금 층으로 맞춤.
- 노드: `MapNodeView`에 정예·야영지 아이콘(`UiArt`의 `node_elite`·`node_camp`, 스크립트로 그린 도형), 이름 "정예"·"야영지"(`UiKeys.Map`).
- 야영지 A: `NodeMapScreen`이 `GamePhase.Camp`에서 야영지 패널(제목, 안내, 효과)과 [쉬기] 버튼(`ExpeditionManager.RestAtCamp`). 버튼 "야영지로".
- 데이터를 15층으로(`DungeonData`, 새 적 둘과 무리, 보스 400), 체인과 스크린샷, 시뮬. Architecture/11·12, Design/03, 08.

## 구현 (13단계)

- 지도 A: `UiPrefabSetup.NodeMap`의 맵을 스크롤 뷰로(뷰는 돌판의 테 14 안, `RectMask2D`와 위아래 16의 흐림, 놋쇠 막대 폭 6, 감도 15 = 휠 한 칸에 약 한 층),
  `NodeMapScreen`이 층 사이 88.5(`FloorSpacing`)로 내용의 높이를 정한다. 첫 층 아래의 여백(이름 자리, 그리고 맨 아래일 때 뷰의 위 끝이 노드의 한가운데를 지나는 만큼)과
  지금 층을 시작할 때의 첫 층 자리에 두는 스크롤은 목업에 없던 것이다: 첫 스크린샷에서 1층의 이름이 바닥에 잘리고 위 끝에 이름 조각이 걸려서 고쳤다.
- 표식: `draw_icons.py`가 목업의 도형 그대로 `Assets/@Art/UI/Icon/node_elite.png`·`node_camp.png`(96x96)를 그린다. `UiArt.NodeElite`·`NodeCamp`, `MapNodeView`가 종류로 표식을 고른다.
- 문구: `Map.Elite`·`Camp`·`EliteHint`·`CampHint`·`EnterCamp`·`AtCamp`·`CampChoose`·`Rest`·`RestHeal`·`RestFatigue`. 패널의 안내 줄과 들어가기 버튼은 고른 노드에 따라 바뀐다.
- 야영지 B: 맵 위의 그늘(검정 60%)과 창(580x320, 놋쇠 테 3), 모닥불·제목·안내, 쉬기 카드(260x160, 가운데. 정비는 14단계에 옆에). 야영지는 같은 화면에서 열리고 닫힌다.
- 데이터를 15층 출발값으로(`DungeonData`, 새 적 둘과 무리, 보스 400). 시뮬은 `Docs/Design/08_Simulation_Report.md` §9.
- 게임의 모습: `game/*_implemented.png`(스크린샷 `20261006-b13b`: 시작 지도, 12층에서 다음 층의 정예를 고른 지도, 14층에서 야영지를 고른 지도, 15층 야영지의 창, 영어의 창).
  지도는 시드마다 다르다(스크린샷의 런은 OS 난수).

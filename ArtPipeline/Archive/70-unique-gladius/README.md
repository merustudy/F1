# Round 70 — 첫 유니크 "글라디우스": 롱소드 + 숫돌 + 숫돌 (2026-10-16, 검토)

목업과 시뮬 측정이다. 호출 없음, 게임의 코드·데이터 변경 없음. 결정 관문 **G18**(아이템 조합)과 Design/02 §4의 【검토】 유니크에 닿는 일이라 설계를 보고하고 승인 뒤 구현한다.

## 지시

2026-10-16 사용자: "유니크는 예제로 롱소드 3성 + 숫돌 3성 + 숫돌 3성으로 만드는 '글라디우스' 아이템을 만들어보자".

## 기록된 것

- Design/02 §4 【검토】(2026-10-07 사용자 의도, Slice C 후보): 유니크 아이템은 금(3성) 아이템을 합쳐 만들고 **한 전투에 하나만** 가진다. 툴팁은 Round 42 목업 7의 **명패 머리 카드**로 보관(Architecture/12 "툴팁" 보관).
- G18(Roadmap "결정 관문 — 미결", `Archive/59-item-combination/README.md` "재검토"): 권장은 **야영지의 담금질**(장소 = 야영지의 정비, 대가 = 쉬기 포기 + 피로 +20, 파티에 하나, 결과 = 성질 하나가 바뀐 유니크), 재료는 "3성 + 같은 3성". 숫돌을 재료(촉매)로 쓰는 길(3의 a)은 Slice C의 지역 촉매로 미뤘다.
  시험 시뮬(2026-10-13): 담금질한 파티의 보스전은 "맞히는 적 +1"이 +2.4%p, "치명타 25%"가 +0.4%p. 아픈 채 담금질하면 77%까지 떨어진다(대가가 진짜다).
- 이번 지시는 G18의 재료를 **숫돌 촉매(3의 a)** 쪽으로 정하는 것이고, "담금질"이라는 말(사용자 결정)을 그대로 쓴다.

## 시뮬 측정 (저장소 밖 복사본, 22단계 데이터, 시드 1, 기본 파티, balanced 3,000회)

재료가 보드에 갖춰지는 빈도를 쟀다. "켜짐" = 숫돌의 ★이 롱소드 위에 있는 것(`StarRules.Sources`). 롱소드는 기사와 마검사의 기본 무기다(상점·전리품에는 없다).

| 무엇 | 지금 정책 | 숫돌을 먼저 사는 정책 |
|---|---|---|
| 야영지 /원정, 15층 야영지에 닿는 원정 | 1.53, 69.6% | 1.53, 69.1% |
| 상점에 숫돌이 있을 확률 | 70% (물건 11종에서 8개, 가중치 8/98) | 같음 |
| 숫돌을 산 원정 (1개 / 2개 / 3개) | — | 34% / 8.3% / 0.5% (0.52개/원정) |
| 15층 야영지에서 숫돌 보유 2개 이상 | 1.1% | 10.5% |
| 15층 야영지의 롱소드 단계 일반 / 1성 / 2성 / 3성 | 77% / 15% / 5.6% / **1.9%** | 같음 |
| **롱소드(단계 무관) + 숫돌 둘 켜짐** (어느 야영지든) | **0 / 3,000** | **0.1%** |
| 롱소드 3성 + 숫돌 3성 둘 켜짐 (지시의 레시피) | **0** | **0** |

읽은 것:

1. **지시의 레시피 그대로는 닿을 수 없다.** 롱소드는 기본 무기라 합치기가 없고 정비(야영지, 원정에 1.5번)로만 오른다: 3성은 정비 셋이 필요해 15층 야영지에서 1.9%. 숫돌 3성 둘은 숫돌 여덟을 합치거나 정비를 더 써야 해 0이다.
2. **숫돌 둘을 한 롱소드에 켜는 것도 드물다.** 공급(상점 1.1번 방문 × 재고 70% × 8코인)과 **자리**(3×3 배낭에서 롱소드가 한 줄을 차지하고, 숫돌 둘은 그 아래 줄의 두 칸이어야 한다. 다른 물건이 먼저 들어가면 자리가 없다)가 막는다. 정책이 숫돌을 먼저 사도 0.1%. 계획하는 사람(상점을 찾고 새로고침하며 아래 줄을 비워 둠)은 더 자주 만들겠지만, 시뮬의 정책으로는 못 보인다.
3. 그래서 유니크의 "드묾"은 **단계가 아니라 재료의 조합과 자리**에서 오게 하는 것이 맞다. 단계 조건을 걸면 사실상 없는 콘텐츠가 된다.

## 제안 (【제안】 — 승인 전에는 【확정】으로 적지 않는다)

### 규칙

1. **레시피**: `RecipeData.csv`에 적는다 — 결과 `gladius`, 바탕 `longsword`, 촉매 `whetstone` × 2. 조건은 **보드의 배치**다: 바탕 무기의 ★ 칸에 촉매의 별이 켜져 있어야 한다(지금 숫돌이 롱소드의 피해를 올리는 그 배치). **단계는 묻지 않는다**(위 1·2).
2. **장소와 때**: **야영지의 담금질**(G18의 틀). 야영지 창에 재료가 갖춰진 보드가 있을 때만 셋째 카드 "담금질"이 선다. 정비처럼 두 걸음(카드 → 재료와 결과를 보이는 확인 → 담금질하기).
3. **대가**: 숫돌 둘이 사라진다, 그 야영지에서 쉬지 않는다(정비도 못 한다), 담금질한 용병의 피로 +`ForgeFatigue`(데이터, 출발값 20. G18의 시험값). 100을 넘으면 다음 전투에 들어서며 붕괴를 판정한다(지금 엔진의 조건).
4. **결과 글라디우스**: 롱소드가 있던 자리에 **2×1**(5칸 → 2칸), **기본 무기로 남는다**(피로 0), **단계는 롱소드의 단계 그대로**(더 정비할 수 있다. 합치기는 없다 — 둘째가 없다).
   무기 장비 / 근접 / 쿨다운 3.0초 / 앞에서 2번째 자리까지 / **치명타 10%**(단검과 같다: 짧은 칼) / 피해 일반 **4-6**(= 롱소드 2-4 + 숫돌 +1 둘. 단계의 퍼센트가 곱해져 1성 8-12, 2성 12-18, 3성 16-24: 3성이면 "3성 롱소드 + 3성 숫돌 둘"의 16-24와 같다) / **성질: 맞히는 적 +1**(`EnemyFront`의 `Reach` 2 = 앞의 적 둘. 새 효과 타입 없음, G18 시험에서 +2.4%p).
   상점·전리품에 없다(`ShopWeight` 0, `Price` 0). 적도 들지 않는다.
5. **유니크**: `ItemData`의 `Unique` 열. 파티에 하나(있으면 담금질 카드가 서지 않는다). 저장은 아이템 id로 충분하고 검증이 "유니크는 하나"를 본다(버전 그대로).
6. **레시피는 숨기지 않는다**: 숫돌과 롱소드의 카드에 "야영지에서 롱소드의 위아래에 숫돌 둘을 켜고 담금질 → 글라디우스" 한 줄. 담금질 카드와 확인 걸음에 재료와 결과가 적힌다.
7. **공급 레버 하나**(권장): 숫돌의 `ShopWeight` 8 → **16**(재고 확률 70% → 약 93%). 값 8은 그대로. 구현에서 시뮬로 재어 띠(클리어 60~70%, 보스전 85~92%) 안인지 본다. 더 센 레버(정예의 전리품에 숫돌, 상점의 숫돌 고정 칸)는 플레이 뒤.
8. **시뮬**: 정책에 "롱소드가 있는 용병에게 숫돌을 둘까지 사서 롱소드 아래에 둔다"와 "야영지에서 재료가 갖춰지면 담금질(아프면 쉰다)"을 더하고, 보고에 담금질 /원정과 글라디우스를 가진 파티의 보스전을 더한다.
9. **G18**: 이 예제가 G18의 재료를 **촉매(숫돌)** 쪽으로 정한다(4안의 틀 + 3의 a). "3성 + 같은 3성"은 하지 않는다(판정 4). 둘째 유니크(다른 바탕 무기 + 다른 촉매)는 지역을 만들 때(Slice C).

## 재검토: 롱소드 3성 + 숫돌 3성 (2026-10-16, 저장소 밖 복사본, 3,000회)

정책 셋으로 쟀다: 지금 정책 / 숫돌을 먼저 사서 롱소드에 켜는 정책 / 거기에 롱소드·숫돌을 먼저 정비하는 정책(지금 정책이 이미 앞 열의 첫 아이템 — 기사의 롱소드 — 을 먼저 정비해서 셋째는 둘째와 같았다).

| 무엇 (원정 기준) | 지금 정책 | 숫돌 먼저 |
|---|---|---|
| 야영지 수 0 / 1 / 2 / 3 / 4 / 5+ | 24% / 26% / 29% / 15% / 4.5% / 1.1% | 같음 |
| 롱소드 3성(어느 야영지에서든) | 2.7% | 2.6% |
| 숫돌 3성이 보드에 | 0.17% | 0.63% |
| 롱소드(단계 무관) + 숫돌 하나 켜짐 | 4.3% | **11.0%** |
| 롱소드 3성 + 숫돌 하나(단계 무관) 켜짐 | 0.07% | 0.07% |
| **롱소드 3성 + 숫돌 3성 켜짐 (판정의 레시피)** | **0** | **0** |

읽은 것:

1. **막는 것은 야영지의 수다.** 기본 무기는 정비로만 오르고(합치기 없음), 원정에 야영지가 평균 1.5번, 셋 이상은 21%뿐이며 아프면 쉰다. 롱소드 3성(정비 셋)이 2.7%인 까닭이다. 숫돌 3성은 정비를 또 둘 쓰거나 숫돌 넷을 합쳐야 해 0.6%, 둘이 함께는 0이다. 담금질할 야영지까지 따로 필요하다.
2. 숫돌 **하나**로 줄인 것은 자리의 문제를 푼다: 숫돌을 먼저 사면 롱소드에 하나가 켜진 원정이 4% → 11%다(사람은 더).
3. 그러므로 "3성 + 3성"을 그대로 두면 사실상 없는 콘텐츠다. 단계의 뜻을 살리려면 **재료의 단계를 결과에 옮기는** 것이 맞다: 롱소드의 단계가 글라디우스의 단계가 되고(3성 롱소드면 3성 글라디우스), 숫돌의 단계는 글라디우스 ★의 세기가 된다(3성 숫돌이면 +4). "3성 롱소드 + 3성 숫돌 → 3성 글라디우스 + ★ +4"가 **가장 좋은 경우**로 남고, 더 낮은 재료는 더 낮은 글라디우스를 준다.
   - 구현은 단순하다: 아이템에 단계는 하나뿐이므로 글라디우스의 단계 = 롱소드의 단계, ★의 세기 = `StarDamage` × 단계(지금 규칙 그대로: 1성 +2, 2성 +3, 3성 +4). 숫돌의 단계를 따로 옮기려면 아이템에 둘째 단계가 필요하다 — 하지 않는다. 대신 **숫돌의 단계가 롱소드보다 높으면 글라디우스의 단계를 숫돌의 것으로**(둘 중 높은 쪽) 둔다: 숫돌을 키운 보람이 남고 규칙은 한 줄이다.
4. 3성을 꼭 지키려면 레버는 야영지 쪽이다: 야영지의 수를 늘리거나(던전 데이터 `CampChancePercent`·`CampMinFloor`), 정비가 기본 무기는 두 단계, 정예 처치가 기본 무기를 한 단계. 모두 16단계(맞추기)의 수치를 흔든다. 플레이 전에는 권하지 않는다.

### 4의 모양 (`mock-gladius-stars.png`)

"중앙 상하로 인접한 1칸씩"은 가운데 칸이 있는 **3×1**에 맞는다. 2×1이면 가운데가 없어 첫 칸(또는 두 칸 모두)의 위아래가 된다.

| 모양 | 읽은 것 |
|---|---|
| **(a) 3×1, 가운데 칸의 위·아래 ★ (권장)** | 롱소드 자리에 그대로 들어가 보드가 흔들리지 않고, 소모된 숫돌의 칸이 비어 그 아래에 단검을 두면 글라디우스가 그것을 벼린다(+4). 위쪽 ★은 롱소드가 맨 윗줄에 있으면 틀 밖이라 쓰이지 않는다(숫돌도 같다) |
| (b) 2×1, 첫 칸의 위·아래 ★ | 칸을 아낀다(5 → 3)는 보상이 더 있지만 "중앙"이 없고, 롱소드 자리에서 한 칸이 비어 보드가 바뀐다 |

### 수치 (판정 5 "권장안", 재료가 하나로 바뀐 것을 반영)

- 피해 일반 **3-5**(롱소드 2-4 + 숫돌 +1) × 단계(1성 6-10, 2성 9-15, **3성 12-20** = 3성 롱소드 8-16에 3성 숫돌 +4). 치명타 10%, 쿨다운 3.0초, 앞에서 2번째 자리까지, **맨 앞 적 둘**(`Reach` 2), **★ 위·아래(가운데 칸) `StarDamage` 1**(단계 곱: 3성 +4), 근접, 기본 무기로 남음(피로 0), 상점·전리품 없음, 파티에 하나, 더 정비 가능, 합치기 없음.
- 데이터는 지금 열로 다 적힌다(`Stars` `1:-1+1:1`, `StarDamage` 1, `Effect1Reach` 2): 효과가 있는 아이템도 ★을 가질 수 있고(`ItemData` 검사는 "효과 없는 아이템은 별이 있어야 한다"뿐), `StarRules`는 별 아이템이 발동하는지 묻지 않는다. 새 열은 `Unique` 하나, 새 파일은 `RecipeData.csv`.

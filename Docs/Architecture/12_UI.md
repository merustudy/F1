# 12. UI

`UIManager`, 화면(Screen)과 View, 화면 Prefab을 만드는 Setup 코드, UI Test를 소유한다.
문구와 Font는 `06_LOCALIZATION.md`, 게임 단계와 명령은 `11_APPLICATION_FLOW.md`, Address와 Scope는 `04_RESOURCES_ADDRESSABLES.md`가 소유한다.

## 구조

```text
Assets/@Scripts/UI              Namespace F1.UI
├─ UIManager        화면 하나를 Main Scene의 UI Root에 띄운다
├─ UIScreen         화면의 Base. ScreenId, ScreenCatalog (Address, Scope, 단계 -> 화면)
├─ Screens/         TitleScreen, LobbyScreen, NodeMapScreen, BattleScreen, SettlementScreen
├─ Views/           화면 안의 조각: RosterEntryView, PartySideView, PartyColumnView, BattleUnitView, BattleBoardView, FigureView, UiBar, SilhouetteOutline(실루엣을 외곽선으로), MerchantGridView(상인의 격자: 상점의 물건) ...
├─ TierStyle        아이템 단계의 표시: 외곽선의 굵기, 별의 수, 단계 표의 치수
├─ ExpeditionArt    원정의 화면이 쓸 그림(유닛의 그림, 유닛의 공격·피격 자세, 아이템의 아이콘)을 읽어 둔 것
├─ FieldLayout      전장에 Column이 서는 자리. 전투 화면과 파티 쪽이 함께 쓴다
├─ UiKeys, UiStrings, UiText, BattleLogText     문구
└─ UiPalette        색

Assets/@Scripts/Editor/Setup/Ui   UiBuild(도구), UiPrefabSetup.*(화면별 Builder)
Assets/@Prefabs/UI                <ScreenId>Screen.prefab, SaveErrorOverlay.prefab, UiPrefabStamp.txt (생성물)
```

## 화면의 역할

- 화면은 **상태를 보여 주고 명령을 전달한다.** 규칙을 계산하지 않는다. 명령이 가능한지는 Manager에 묻는다
  (`CanDepart`, `CanPlaceInParty`, `CanMoveToRow`, `AvailableNodes`, `CanUsePotion`).
  어느 열에 설 수 있는지도 규칙이다. 화면은 열마다 물어서 버튼을 켜고 끈다.
- 화면은 `Managers`를 통해 `RunManager`, `ExpeditionManager`, `SettingManager`, `DataManager`를 쓴다. 소리는 `SoundManager`로 낸다(`14_SOUND.md` "소리를 내는 자리"). 상태 객체를 직접 바꾸지 않는다.
  `ResourceManager`는 그림을 읽을 때만 쓴다("유닛의 그림", "전투 화면"의 배경).
- 명령을 낸 뒤에는 상태를 다시 읽어 그린다(`Refresh`). 단계가 바뀌었을 수 있으면 `GoToCurrentPhase`를 부른다.
- 화면은 한 번에 하나다. 팝업은 화면 Prefab 안의 Panel을 켜고 끄는 것으로 한다(확인, 결과, 런 종료).
- 연출 완료를 기다려 명령을 내지 않는다. 전투 결과와 정산은 이미 확정돼 있고(`11_APPLICATION_FLOW.md`), 화면은 그것을 보여 줄 뿐이다.

| 화면 | 단계 | Scope | 하는 일 |
|---|---|---|---|
| `TitleScreen` | 앱을 켰을 때, 로비에서 타이틀로 나왔을 때 | App | 새 런(진행 중이면 확인), 이어하기, 종료, 설정 줄(언어, 음악, 효과음), Save 파일 상태 알림 |
| `LobbyScreen` | `Lobby` | Lobby | 날짜, 로스터와 피로도·고통(아래), 파티와 열(용병마다 열 버튼과 제외), 던전의 일수, 쉬기(피로도가 내려가는 만큼), 출발(피로도는 막지 않는다), 런 종료 안내 |
| `NodeMapScreen` | `NodeMap`, `Camp` | Expedition | 위로 스크롤하는 맵과 노드 선택(적은 보이지 않는다 → `Docs/Design/03` §1), 야영지의 창, 파티 쪽(전투와 같은 열), 포션, 인벤토리 팝업 |
| `BattleScreen` | `Battle`, `Loot` | Expedition | 전투 진행(배속, 정지), 유닛(그림 자리, 발밑 표시, 머리 띠와 아이템 칸의 보드), 포션, 후퇴, 결과와 사망 설명, 끝난 뒤의 로그 보기. **이긴 뒤**(Round 47): 무대 위의 띠, 바닥의 전리품 줍기(보드의 칸이나 인벤토리로), 노드 맵의 보드, [계속]. `Loot` 단계(앱을 닫았다 연 뒤)는 이 화면의 "이긴 뒤" 모습이다(18단계의 전리품 화면은 Round 47에 지웠다) |
| `SettlementScreen` | `Settlement` | Expedition | 귀환 정산 보고(살아 돌아온 용병마다 쌓인 피로도와, 고통인 채 돌아왔으면 그 이름) |

## 피로도와 붕괴의 상태 (2026-10-06 Round 33 목업 "C", Round 36 목업 "C"·"B" 승인)

규칙은 `Docs/Design/04_Lobby_100Day_Economy.md` §3. 피로는 어디서나 **칸 열 개**(다키스트 던전식)이고, 붕괴의 상태(고통·각성)는 **이름**으로 보인다.

- 로스터 줄의 피로도: 막대 자리(590x14)에 칸 열 개(사이 4)가 늘어서고, 칸 하나가 `MaxFatigue`의 10분의 1이다(200이면 20씩).
  칸은 쌓인 만큼 왼쪽부터 찬다(마지막 칸은 일부만). 붕괴의 문턱(`FatigueBreakdown`) 앞의 칸은 연보라 `UiPalette.FatigueBar`, 문턱부터의 칸은 붉은 보라 `FatigueDanger`다(100이면 뒤의 다섯).
  비어 있는 칸은 막대의 홈 색(`Slot`)이다. 채움과 색은 세 화면이 같은 `FatiguePips.Show`로 한다.
- 글 "피로도 N/200"은 문턱 아래면 피로의 연보라(`Fatigue`), 문턱부터는 붉은 보라다. 칸은 `UiPrefabSetup.Lobby.BuildRosterEntry`, 채움과 색은 `RosterEntryView`.
- 고통인 채 돌아온 용병(Round 36): 글이 "피로도 128/200 · 공포"(붉은 보라)가 되고, 패시브 줄의 오른쪽 끝(410부터 200, 오른쪽 정렬, 18)에 고통의 효과("아이템이 25% 느리게 돈다". 데이터의 `Description`)가 붉은 보라로 선다.
  목업은 효과를 피로 글의 왼쪽에 두었지만 거기에는 직업이 있어 패시브 줄의 끝으로 옮겼다(패시브 글의 폭 590 → 380). 로비는 각성을 보이지 않는다(원정이 끝나면 풀린다).
- 파티 쪽과 전투의 발밑 표시(Round 36, "C"): HP 막대 아래에 막대와 같은 폭으로 **칸 열 개**(높이 4, 사이 2. 26부터)가 있고, 그 아래의 상태 줄(32부터)에 **상태의 이름**이 붙는다.
  파티 쪽은 직업 줄이 "마검사 · 공포"가 되고(`UiText.JobLine`. 고통은 붉은 보라, 각성은 금빛 `UiPalette.Virtue`), 전투는 상태 줄의 빈사·화상 다음에 이름이 선다(`BattleUnitView`. 적에게는 칸도 이름도 없다).
  발밑 표시의 높이는 46 → 50이라 파티 쪽의 그림이 4 올라갔다("전투 화면", "파티 쪽").
- 상태의 효과는 파티 쪽에서 **상태 줄을 누르면** 설명 줄에 "공포: 아이템이 25% 느리게 돈다"로 나온다(`PartyColumnView.StateClicked` → `PartySideView`. 상태가 없으면 줄은 눌리지 않는다). 다시 누르거나 칸을 누르면 내려간다. 전투에서는 누르지 않는다.
- 정산: "생환자의 피로도: 로언 128 (공포), 카이 30"(`SettlementReport.SurvivorStates`).
- 붕괴·각성·쓰러짐의 연출은 "연출"의 표.

## UIManager

- `ShowAsync(ScreenId)`: 새 화면을 만들고, 그 화면이 쓸 것을 읽게 한 뒤(`PrepareAsync`) `Open`하고 이전 화면을 놓는다. 그 사이 빈 Frame이 없다.
- 바꾸는 동안 이전 화면은 클릭을 받지 않는다. 같은 명령이 두 번 나가지 않게 하기 위해서다. 바꾸는 중에 또 부르면 예외다.
- 화면의 Scope만 열어 둔다. Lobby 화면을 떠나면 Lobby Scope를, 원정 화면들을 떠나면 Expedition Scope를 놓는다.
- Boot의 마지막 단계(BOOT-12)가 타이틀을 띄운다.
- `ScreenShown(ScreenId)`: 새 화면이 `Open`된 뒤 알린다. 16단계의 플레이 기록(`10_TESTING_VALIDATION.md` "플레이 기록")이 듣는다. 화면과 규칙은 이 이벤트에 기대지 않는다.
- `SaveErrorOverlay`는 화면이 아니다. `BindAsync`에서 한 번 만들어 앱이 끝날 때까지 모든 화면 위에 둔다.
  저장이 막히면(`RunManager.SaveBlockedChanged`) 화면 전체를 가리고 "다시 시도"와 "종료"만 받는다.

## 화면 Prefab은 코드로 만든다

- Prefab을 손으로 고치지 않는다. `Editor/Setup/Ui`의 Builder를 고치고 setup을 돌린다.
- 1920x1080 설계 공간에 좌표로 배치한다(`UiBuild.Box`). Canvas는 Expand라서 어떤 화면 비율에서도 이 영역이 잘리지 않는다.
- 목록(로스터, 노드, 유닛, 아이템 칸)은 Prefab 안의 꺼진 Template을 Runtime에 복제한다.
- 직렬화 참조는 Builder가 이름으로 채운다(`UiBuild.SetReference`). 빠뜨린 참조는 `UiPrefabSetup.FindProblems`가 잡는다.
- **한 Prefab 안의 모든 Object 이름은 달라야 한다.** Unity는 다시 만든 Prefab의 id를 이름으로 맞추기 때문에, 이름이 겹치면 만들 때마다
  파일이 바뀐다. 겹치면 Builder가 실패한다.
- Builder 코드나 런타임 UI 코드(`Assets/@Scripts/UI`: Builder가 그 상수로 자리를 잡는다 — 팔레트, 격자의 칸과 줄, 조각의 여백 등)가 바뀌었을 때만 다시 만든다. `UiPrefabStamp.txt`가 둘의 Hash를 기록한다(Round 56: 상인 격자의 8줄이 런타임 상수라 상점 창이 다시 만들어지지 않았던 것을 고침).
  CSV 문구를 고쳐도 Prefab은 바뀌지 않는다(고정 라벨은 Prefab에 Key를 담고, 문구는 Runtime에 String Table에서 온다).
- 원정 화면(전투, 노드 맵과 전리품의 파티 쪽)의 틀과 상태 아이콘은 그림이다("UI의 그림"). 그것과 유닛의 그림, 전투의 배경 말고는 도형 Placeholder다(색 사각형).
  막대의 채움은 Sprite 없이 폭으로 그린다(`UiBar`).

## 문구

- 고정 라벨: Builder가 `UiBuild.LocalizedLabel`로 만든다. 자리(`{0}`)가 있는 Key는 쓸 수 없다.
- 값이 들어가는 문구: 화면이 `UiStrings.Get(UiKeys.X, 값)`으로 만든다. `UIScreen`이 `LocaleChanged`를 듣고 `Refresh`를 부른다.
- Game Data의 이름: `UiText.Name(LocalizedText)`. 아이템과 포션의 설명은 효과 어휘에서 조립한다(`UiText`). 직업 패시브 설명은 데이터가 가진다.
- 전투 로그와 사망 설명은 `BattleLogText`가 이벤트 로그에서 만든다. 사망 원인을 읽는 것은 Domain의 `BattleLog.PartyDeaths`다.
  사망 문장은 셋이고 `BattleLogText.DeathKey`가 고른다: 유예가 끝난 뒤의 사망과 유예가 깨진 사망은 마지막 피격과 굴림을 적는다(`Death.AfterGrace`·`Death.GraceBroken`).
  **쓰러짐**(`DeathCause.Collapsed`: 빈사에서 피로가 가득 차 쓰러진 것. `Died` 직전의 `Collapsed`가 C = 1)은 피격도 굴림도 없는 죽음이라 빈사와 사망의 시각만 적는다(`Death.Collapsed`).
  HP 0으로 들어온 용병은 한 번도 맞지 않고 동료의 빈사·사망의 피로로 이렇게 죽을 수 있어 마지막 피격이 없다(2026-10-09에 고친 버그: 그 사망 문장이 없는 포션 id를 찾아 결과 창·띠가 던졌다).
  Test: `BattleLogTextTests`(EditMode), 원인은 `BattleEngineTests`의 `PartyDeaths_…`.

## 열을 보여 주는 방식

- 열의 이름은 고정 라벨이다(`Common.Row1`~`Row4`, `UiText.RowKey`). 열의 수는 구조라서 Builder가 `BattleRows.Count`만큼 만든다.
  전투 화면과 파티 쪽에서는 유닛의 보드 머리 띠의 금 징에 열 번호만 적는다.
- **파티가 설 수 있는 열의 수는 `PartySize`**이고 데이터다(지금은 한 쪽의 열 수와 같은 넷). 파티의 열에 딸린 것
  (로비의 열 버튼과 파티 줄, 전투 화면의 아군 Column)은 Prefab에 `BattleRows.Count`만큼 있고, `PartySize`가 그보다 적으면 화면이 열 때 넘는 것을 감춘다.
- 로비: 로스터의 용병마다 열 버튼과 "제외"가 있다. 설 수 있는 열만 켜진다. 서 있는 열의 버튼은 강조되고, 눌러도 바뀌는 것이 없다.
- 아이템 설명은 크기와 쓸 수 있는 자리(앞이나 뒤에서 몇 번째까지)를 적는다. 어디서나 쓸 수 있으면 자리는 적지 않는다.

## 유닛의 그림

- 그림 자리(`FigureView`)는 그 유닛의 그림이 있으면 그림을, 없으면 도형 Placeholder(실루엣과 "그림 자리" 글자)를 보여 준다.
  그림이 있는지는 데이터가 말한다: 용병은 직업의 `Figure`, 적은 적의 `Figure`(`05_STATIC_DATA.md`). 읽다 실패한 것을 Placeholder로 바꾸지 않는다.
- 모든 전신 그림은 같은 3:4 캔버스에 같은 바닥선으로 서 있다(`13_ART_PIPELINE.md`). 그래서 그림마다 자리를 맞추지 않는다.
- 적의 그림은 `EnemyData.FigureScale`(백분율)만큼 크게 그린다(`FigureView.SetScale`, `ExpeditionArt.ScaleOfEnemy`): 보스는 150이라 그림 자리(225x300)보다 크게 서고 옆 열과 겹쳐도 된다.
  발은 같은 바닥선에 있고 그림 자리·발밑 표시·Column의 배치는 그대로다(2026-10-04 플레이 피드백 "보스는 훨씬 크게").
  그림은 Column의 폭과 상관없이 **제 크기**(높이 300, 폭 225)로 Column의 가운데 아래에 선다. Column이 그보다 좁으면 그림이 옆 Column으로 넘어가고,
  옆 그림과 겹치는 곳에서는 **앞 열(1열)이 위에** 그려진다(Builder가 뒤 열의 Column부터, 같은 열에서는 파티 다음에 적을 만든다: 적 1열이 파티 1열 위).
  **공격하는 유닛은 공격하는 동안 맨 위에** 그려진다(2026-10-05, Design/10 §5): 돌진과 0.05초 더(`BattleUnitView.Attacking`) 그 유닛의 Column이 모든 Column 위로 가고 끝나면 원래 순서로 돌아온다(`BattleScreen.ArrangeColumns`).
  뒤 열에서 공격하는 유닛의 무기가 앞 열 유닛에 가려지지 않는다. 공격하는 그림이 상대의 발밑 표시를 잠깐 덮는 것은 괜찮다(사용자. 명패였을 때의 결정).
- 그림 자리에는 색 틀이 없다. 빈사, 보호막, 포션 대상은 발밑 막대의 테두리 색(포션 대상은 발밑의 빛도)이 보여 준다. 편은 자리가 말한다("전투 화면").
- 그림은 화면이 열리기 전에 읽는다. `UIManager.ShowAsync`가 `Open` 전에 화면의 `PrepareAsync`를 기다리고, 그림을 보여 주는 화면(노드 맵, 전투, 보상)은
  거기서 `ExpeditionArt`로 Static Data가 이름 붙인 그림 전부(유닛의 `Figure`, 직업과 적의 공격·피격 자세, 아이템의 `Icon`)를 `ResourceManager`의 Expedition Scope에 읽어 둔다.
  그 뒤로 화면과 View는 그림을 기다리지 않는다.
- 유닛의 **얼굴**은 쓰지 않는다. 2026-10-03 V안에서 보드 패널의 얼굴이 빠졌고(보드 패널의 열이 무대 바로 아래라 필요 없어졌다), 2026-10-05에 그림과 읽어 두기도 게임에서 뺐다.
  잘라 내는 도구는 남아 있다(`13_ART_PIPELINE.md` "얼굴").

- 그림 자리에는 발밑 그림자(검은 타원 150x26, 알파 0.35)가 있고, 그림은 발을 축으로 2%만큼 1.8초 주기로 숨쉰다(`FigureView`). 세 화면 모두 같다("연출").
- 용병과 몬스터는 **공격 자세와 피격 자세**를 가진다(`JobData`·`EnemyData`의 `AttackPose`, `HitPose`. Design/10 §2·§5. 몬스터는 2026-10-05). 자세 그림은 그림 캔버스를 가운데에 둔 세 배 폭·8분의 9 높이의 캔버스(2016x1008. 파일은 같은 비율의 2048x1024, `13_ART_PIPELINE.md` "후처리 (`pose`)")이고,
  자세를 보이는 동안 `FigureView.ShowPose`가 그림 자리를 675x338로 넓히고 피벗을 자세 캔버스의 바닥선(아래에서 112/1008)에 두어 발이 같은 바닥선에 선다. 숨쉬기·이동·번쩍임은 자세에도 그대로다.
  전투 화면이 두 편 모두 `Bind`에 자세를 준다. 보스의 자세도 그림처럼 `FigureScale`만큼 크다(`FigureView.ShowPose`가 `SetScale`을 따른다).

## UI의 그림

원정 화면의 틀과 상태 아이콘은 `Assets/@Art/UI`의 Sprite다(`13_ART_PIPELINE.md`). 2026-10-02 목업으로 승인한 전투 UI에 쓰고, 2026-10-04 목업 A안(야영지 장비)과 A3(캔버스 공구 말이)로 꾸몄다("야영지 장비").

- Builder가 Sprite를 Prefab에 직접 넣는다(`UiArt`가 이름과 자리를 가진다). 데이터가 가리키는 그림이 아니어서 Address가 없고, 화면 Prefab과 함께 읽힌다.
- 틀(`panel`, `plate_label`, `name_tag`, `slot`, `button`, `bag`)은 9-slice로 쓴다. 가장자리에 리벳이나 박음질이 있는 틀(`panel`, `bag`)은 늘이지 않고 **타일**로 깐다
  (`Image.Type.Tiled`. `UiArt.Piece.Tiled`가 정한다. 2026-10-03 연출 3차의 질감 틀), 나머지는 늘인다(`Sliced`). 늘어나지 않는 가장자리의 폭(Border)은 `UiArt`가 갖고
  `ArtSetup`이 Import 설정에 넣는다. Sprite는 화면에 쓰는 크기의 2배로 그려져 있다(Pixels Per Unit 200).
  얇은 조각(HP 막대의 틀, 포션 띠, 안내문 판, 보드의 머리 띠)에는 가장자리를 줄여 쓴다(`Image.pixelsPerUnitMultiplier`).
- 늘이지 않는 조각은 Sprite 그대로 놓는다(Border 없음): 양초의 조각(촛대, 몸통, 불꽃, 녹은 윗면, 연기), 해골 더미, 사슬, 빛(`glow`), 노드 표식, 상태 아이콘, 비네트(`vignette`)와 양초의 빛(`candle_dark`, `candle_warm`), 쿨다운의 경사(`charge_ramp`), 보드 머리의 금 징(`gold_stud`),
  쓰러진 용병의 무덤(`grave`. 전신 그림과 같은 캔버스에 그린 소품이라 유닛의 그림 자리에 맞추면 그 바닥선에 선다. "연출").
  비네트와 양초의 빛은 `ArtPipeline/Archive/16-candle-light/draw_pieces.py`가, 쿨다운의 경사는 `Archive/18-cooldown-light/draw_pieces.py`가 도형으로 그린 것이다(09가 그린 비네트는 밝기 경사가 거꾸로였다). 2026-10-03의 다이얼(`dial`)과 고리(`ring`)는 양초가 대신해 없다.
- 색만 다른 상태는 Sprite를 바꿔 낀다: 칸(보통, 고른 것). View가 그 Sprite들을 갖고 있다. 유닛의 상태는 Sprite가 아니라 HP 막대 테두리의 색이다(`UiPalette.RimShield`, `RimDanger`, `RimTarget`. 2026-10-05).
  버튼은 흰 바탕의 Sprite 하나에 색을 입힌다(`Image.color`. 색은 `UiPalette`).
- 막대의 채움과 상태의 테두리(Unity의 기본 둥근 사각형), 쿨다운의 금빛과 어둠과 앞머리의 선, 발밑 그림자, 번개, 떠오르는 글자는 Sprite 없이(또는 Unity의 기본 도형으로) 그린다. 쿨다운 앞머리의 번지는 빛과 어둠의 부드러운 끝만 경사 조각(`charge_ramp`)을 늘여 쓴다.
- 판 없이 무대 위에 놓이는 글(발밑 표시의 숫자와 상태 줄, 배지의 수, 보드 머리의 이름)은 글꼴의 **외곽선 재질**로 그린다(`UiBuild.Outlined`. 재질은 `06_LOCALIZATION.md` "Font").
- 상태 아이콘(보호막, 화상, 빈사, 폭풍)에는 늘 숫자나 글자가 붙는다. 아이콘만으로 뜻을 전하지 않는다.

### 아이템의 아이콘

아이템의 그림은 데이터가 가리킨다(`ItemData.Icon`. `13_ART_PIPELINE.md` "Unity 배선"). 2026-10-03 사용자가 스물한 개를 확정하고 목업대로 연결하게 했다.

- 조각은 아이콘을 **여백 5 안쪽에 비율을 지켜** 놓는다("격자 보드"). 직업의 기본 무기는 3×1, 그 밖의 아이템은 가로 2칸까지라(Round 50과 정정, `Docs/Design/02_Combat_System.md` §4)
  2칸의 가로로 긴 아이콘(녹슨 칼, 조잡한 활, 창 등)은 조각의 폭에 맞춰 줄고 위아래가 빈다. 그림은 지금 아이콘을 줄여 쓴다(다시 그리기는 지시가 있을 때).
  아이콘 파일은 **그려진 부분만** 남긴다(Round 50, `ArtPipeline/tools/trim_items.py`): 띠 칸의 캔버스에 남던 좌우의 빈 둘레 때문에 1×1의 버클러가 점으로,
  2칸의 무기가 목업보다 작게 보였다. 그래서 조각과 바닥의 전리품·상점 타일이 그려진 부분을 상자에 맞추고, 쿨다운의 밝아짐도 그려진 폭을 따라간다.
  아이콘 스물한 개는 2026-10-03의 띠 칸 캔버스(328x80, 328x188, 328x296)에 그린 것 그대로다(사용자 결정 2026-10-04 "다시 그리지 않는다". 다음에 그리는 아이콘부터의 캔버스는 `13_ART_PIPELINE.md` "후처리 (`cell`)").
- 아이콘이 있는 조각에는 이름을 적지 않는다. `Icon`이 빈 아이템은 지금처럼 이름을 적는다.
- 전투의 적 조각에서는 아이콘의 **좌우를 뒤집는다**: 무기의 끝이 아군 쪽을 향한다. 그림을 따로 두지 않고 Scale로 뒤집는다.
- 돌린 아이템은 아이콘도 그만큼 돈다(시계 방향 90도씩. `GridGeometry.ArtTurn`).
- 아이콘은 클릭을 받지 않는다. 클릭은 그 아래의 칸이 받는다("격자 보드").

## 격자 보드 (2026-10-08 19단계, Round 48: "B 방향", "C 가방격자", 쿨다운 "2안", 배낭 3×3·틀 3×8, 돌리기는 백팩 배틀즈; 2026-10-09 Round 49: 디아블로 2의 모습)

- **합치기의 표시**(Round 35): 아이템을 들면(보드의 것, 인벤토리의 것, 상점의 물건, 바닥의 전리품) 그것이 **합쳐질 아이템의 조각**은 어두운 막(60%) 위에 "합치기 → 동"처럼 합쳐서 되는 단계를 적고(글은 단계 표에서 6 띄워 올린다), 별도 그 단계의 것이다
  (`ItemSlotView.MergeMark`). 어느 칸이 합쳐지는지는 Manager에 묻는다(`MergesAt`, 전리품은 `LootMergesAt`). 고른 아이템의 줄에는 합쳐질 아이템이 어느 보드에든 있을 때
  "같은 단검·동 위에 놓으면 합쳐서 은 하나가 됩니다."(일반은 단계 없이 "같은 단검 위에 놓으면 합쳐서 동 하나가 됩니다.")를 덧붙인다(`HasMergeTarget`, `UiText.MergeHint`). 설명이 길면 글자가 작아진다(설명 줄은 두 줄 자리, 19에서 14까지. Round 46). 카드가 모든 줄을 보인다.
- 패널의 **오른쪽 판은 그 화면의 것**이다(Round 46: 920x218, 전의 절반): 위에서부터 머리 줄(노드 맵: 고른 노드의 층과 종류(34), **그 옆 같은 기준선에 안내**(20, 흐림. 남는 폭만 쓰고 길면 안내가 줄여진다: `NodeHeading`),
  전리품: 머리 줄 대신 줍는 안내 두 줄), 설명 두 줄(고른 아이템의 설명 또는 보드 쓰는 법), 버튼 줄(높이 64. 노드 맵: "인벤토리로", "인벤토리 보기", "전투 시작"(야영지를 고르면 "야영지로").
  전리품: "인벤토리에 넣기", "인벤토리로", "인벤토리 보기", "두고 가기"). 버튼은 전투 헤더와 같은 버튼 그림이다.
- 들어가지 않는 글자는 줄여서 넣는다: 보드 머리의 이름, "앞으로"와 "뒤로"(`UiBuild.ShrinkToFit`).
- Column과 패널의 열은 **살아 있는 용병이 선 열**에만 보인다. 죽은 용병은 전투에서처럼 보이지 않는다(죽은 것은 정산이 말한다).
  파티가 설 수 없는 열(`PartySize` 밖)은 감춘다.
- "앞으로"는 1열 쪽(오른쪽)으로, "뒤로"는 그 반대로 옆 열의 용병과 자리를 맞바꾼다. 자리가 바뀌면 Column과 패널 열의 내용이 바뀐다.
- **포션**은 전투와 같은 띠, **같은 자리**(왼쪽 위 x 30, 헤더 아래 92)다(Round 46. 무대의 그림은 210부터라 띠(92~176)와 겹치지 않는다).
  노드 맵과 전리품에서는 보여 주기만 한다(쓰는 것은 전투, 받는 것은 상점).
- 조작은 **손**이다(위 "격자 보드"): 아이템을 누르면 집어 마우스에 태우고(Round 54) 칸을 누르면 든 것의 가운데가 마우스에 오는 자리에 놓으며, 든 동안 우클릭·휠·R로 돌린다. "인벤토리로"(패널의 오른쪽)를 누르면 든 아이템이 인벤토리로 빠진다(`CanMoveToInventory`).
- 아무것도 들지 않았을 때는 안내문(쓰는 법과 돌리기)이, 든 동안은 그 아이템(가방이면 가방)의 설명이 패널의 오른쪽에 보인다. 화면이 가진 것을 든 동안(상점의 물건)은 그 화면의 안내다.
- 아이템의 설명(고른 아이템의 줄, 인벤토리 팝업의 줄, 상점 타일의 사실)은 피로를 끝에 적는다(`UiText`): 피로를 내는 장비는 연보라로 "전투마다 피로 +1",
  기본 무기는 흐린 글로 "기본 무기: 피로 없음", 나머지는 적지 않는다. 한 줄 설명은 효과 뒤의 끝이다.

### 인벤토리 팝업 (2026-10-09 Round 49: 디아블로 2의 인벤토리 창, V5 "디아블로식 격자"; 2026-10-10 Round 52: 무대 위, 칸 50, I)

- 인벤토리는 줄이 아니라 **팝업**이다. "인벤토리 보기"를 누르면 화면 오른쪽(맵, 또는 전리품의 판. 헤더 아래 92부터 오른쪽 판의 표 위 826까지)을 덮는 창이 열리고 버튼은 "인벤토리 닫기"가 된다.
  창은 돌 상자(`table`)이고 위에서부터: 가운데 어두운 판의 제목 "인벤토리"(금, 25)와 오른쪽의 **쓴 칸 / 전체 칸**("24 / 30칸". 뼈색), **인벤토리 격자**(`InventoryGridView`: 칸 66·사이 2의 `InventoryWidth`×`InventoryHeight`, 돌 테 6에 가라앉음),
  격자 왼쪽 아래의 코인 판(코인 그림과 수), 아래쪽에 **든 아이템의 툴팁**(디아블로의 검은 상자, 가운데 정렬: 이름(Round 57부터 **등급 없이** 이름 · 단계: `UiText.TooltipTitle`)은 희귀도 색, 사실 한 줄씩, 효과는 파랑, 피로는 제 색, 끝에 돌리기 안내. `UiText.TooltipLines`. 든 것이 없으면 숨김),
  맨 아래 쓰는 법("아이템을 누르면 손에 듭니다 · 왼쪽 보드나 이 격자의 빈 칸을 누르면 그 자리에 놓입니다").
- 격자의 아이템은 보드와 같은 조각(남색, 별, 합치기 표시; 피로 표는 없다: 인벤토리의 아이템은 피로를 내지 않는다)이 그 자리와 방향으로 놓인다. 칸이 클릭과 포인터를 받는다.
- 칸을 누르면 그 아이템을 손에 든다(그 방향 그대로). 든 아이템은 왼쪽 보드의 칸이나 **격자의 빈 칸**에 놓인다(든 것의 가운데가 마우스에 오는 자리, 격자 밖이면 안으로 당김. Round 54). 격자 위의 그림자는 초록(빈 칸)과 빨강(다른 아이템과 겹침: 바꾸기는 없다)이고 보드와 같이 한 덩어리다(Round 53). 조각은 보드의 조각과 같다(칸마다 남색, 같은 색).
  보드의 아이템을 든 채 격자의 빈 칸을 누르면 그 자리로 빠진다(`CanMoveToInventoryAt`). 인벤토리의 아이템은 격자 안에서 옮긴다(`CanMoveInInventory`). 지금 자리를 누르면 내려놓는다. 우클릭은 아무것도 들지 않았을 때 그 아이템의 카드다.
  화면이 가진 것(상점의 물건, 바닥의 전리품)은 버튼으로 넣거나(첫 빈 자리) Round 55부터 빈 칸에 바로 놓는다(그 자리에 사지고 주워진다).
- 인벤토리에 자리가 없으면 그리로 가는 버튼이 꺼진다: 이긴 뒤 전투 화면의 "인벤토리에 넣기"(`CanTakeLootToInventory`), 파티 아래의 "인벤토리로"(`CanMoveToInventory`), 상점의 "인벤토리에 넣기"(`CanBuyToInventory`),
  그리고 밀려나는 아이템이 들어갈 자리가 없는 찬 칸. 자리는 넓이가 아니라 격자의 빈 자리다(Design/03 §5). 보드의 아이템을 집어 다른 보드로 옮기는 것은 인벤토리가 차도 된다(`CanPickItem`). 가방은 인벤토리에 넣지 않는다.
- 손이 든 것은 한 번에 하나다: 보드의 아이템, 보드의 가방, 인벤토리의 아이템 가운데 하나만 밝은 남색이다. 다른 것을 들면 앞의 것은 내려놓는다.
- "인벤토리 보기 (I)/닫기 (I)" 버튼은 보드 패널의 오른쪽 버튼 줄에 있다(노드 맵. 이긴 뒤 전투 화면은 "인벤토리에 넣기" 옆). **I 키**(`InventoryKey`)는 버튼이 보이고 눌리는 동안 버튼과 같다
  (`NodeMapScreen.PressInventoryKey`, `BattleScreen.PressInventoryKey`. 든 채로도. 닫으면 인벤토리에서 든 것은 손을 비운다). 야영지의 정비와 전투 중에는 버튼이 없어 키도 없다.
- **Round 52(사용자 "b안")의 자리**: 창(`InventoryWindowView`)은 화면 오른쪽 대신 **용병의 무대 위**에 뜬다: 헤더 아래 92부터 보드 패널 620까지의 왼쪽 960을 덮는 그늘(`UiPalette.InventoryShade` 35%, 클릭을 받음)과
  그 위쪽의 돌 상자(x 8, 폭 944, 높이 350). 격자는 상자의 왼쪽 위(24, 68)이고 **칸은 보드와 같은 50**(`InventoryGridView.Square` = `GridGeometry.Square`), 코인 판은 격자 아래, 든 아이템의 툴팁은 격자 오른쪽(글 15, 위에서 아래로 자람),
  쓰는 법은 맨 아래(글 15, "아래 보드나 이 격자의 빈 칸을 누르면 … · I: 열고 닫기"). 위의 칸 66·오른쪽 자리는 Round 49의 것이다. 이긴 뒤 전투 화면도 같은 창을 같은 자리에 갖는다(아군 쪽 무대. 바닥의 전리품은 적 쪽이라 가리지 않는다):
  격자의 칸을 누르면 `LootHand`가 집거나 놓고(Round 55부터 바닥의 전리품도 빈 칸에 놓이면 그 자리로 주워진다: `IOutsideHand.PlaceInInventory`. 상점의 물건도 같이 그 자리에 사진다), 우클릭은 카드를 창 안의 조각 옆에 연다.
- Builder는 `UiPrefabSetup.PartySide`(`BuildInventoryPopup`: 두 화면이 쓴다, `BuildInventoryGrid`), 뷰는 `InventoryWindowView`(채우기)와 `InventoryGridView`, 화면은 `PartySideView`·`BattleScreen`(열고 닫기, 격자의 이벤트), 손은 `BoardHand`(`InventoryGhost`, `ClickInventory`).

### 노드 맵의 오른쪽 (2026-10-06 Round 34: 지도 "A", 야영지 "B")

### 상점 — 상인 (2026-10-07 Round 44 창 "A"; 2026-10-10 21단계: 디아블로 2의 상인, Round 55 2차 목업; Round 57 마우스를 올리면 툴팁, 안 B; Round 58 가방 줄)

## 툴팁: 아이템 카드 (2026-10-07 Round 42, 목업 안 1 + 자리 P1 승인)

아이템의 정보는 **우클릭**으로 열리는 **카드**(`ItemTooltipView`)로 본다(2026-10-08 Round 47, 사용자 "아이템 정보는 마우스 우클릭 툴팁으로". 그 전 Round 42는 좌클릭 = 고르기 + 카드였다).
좌클릭은 집기와 놓기만 한다. 레퍼런스(Backpack Battles)는 마우스를 올리면 열리지만 우리 조작은 누르는 손이라 **우클릭에 열리고 다음 누름에 닫힌다**(든 동안의 우클릭은 돌리기: "격자 보드"). 우클릭은 아이템이 보이는 모든 곳에서 같다:
파티 쪽의 보드 칸, 전투의 아군·적 조각, 이긴 뒤의 보드 칸과 바닥의 전리품, 상점 타일, 인벤토리 격자의 칸(`RightClick`: 버튼 옆에 사는 조각. 버튼이 꺼져 있어도 받는다).
목업과 레퍼런스는 `ArtPipeline/Archive/42-item-tooltip/README.md`, 우클릭은 `ArtPipeline/Archive/47-loot-in-battle/README.md`.

- **모양**(Round 49 V3: 디아블로의 툴팁): 검은 반투명 판(`TooltipFill` 86%, 모서리 4)에 회색 가는 선(`TooltipLine`), 폭 400, 안쪽 여백 16(왼쪽 24). 줄은 모두 **가운데 정렬**이다: 제목(24. `UiText.ItemTitle`: 이름 · 단계 · 등급. **희귀도 색** `UiPalette.Rarity`), 회색 가는 줄(1),
  사실(19, 흰색: 분류 / 크기 / 쿨다운 / 자리), 효과(20, 줄마다, **매직 파랑** `TooltipEffect`), 피로(19: 연보라 "전투마다 피로 +N" 또는 흐린 "기본 무기: 피로 없음"), 파티 쪽에서 합칠 것이 있으면 합치기 안내(19, `UiText.MergeHint`).
  글은 `UiText.ItemCard`가 설명 줄과 같은 조각으로 낸다(새 문구 없음). 단계의 띠는 없다. 높이는 글에 맞춰 늘어난다(VerticalLayoutGroup + ContentSizeFitter).
- **자리**(`TooltipPlacement`, 순수 함수. 좌표는 화면의 왼쪽 위 기준, y는 아래로): 파티 쪽(노드 맵·전리품)은 **보드 패널 위 8**에, 누른 아이템의 조각에 가운데를 맞추고 화면 끝에서 12 안으로 민다.
  아래 가운데의 **꼭지**(회색 테의 검은 마름모를 패널 쪽 절반만 보인 것. 모서리에서 16 안)가 그 조각을 가리킨다. 다른 보드와 "합치기 →" 표시, 패널 오른쪽은 가리지 않는다(그 열 용병 그림의 아래쪽과 앞으로·뒤로를 잠시 덮는다).
  전투는 **보드 옆**: 아군의 카드는 보드 왼쪽 10, 적의 카드는 오른쪽 10(가운데는 양초), 누른 칸의 높이에, 패널 안(위 6, 아래 12)과 화면 안에 머문다.
  이긴 뒤 바닥의 전리품은 그 아이콘의 **왼쪽**(전장의 상자 안에서), 보드 칸은 파티 쪽처럼 패널 위, 상점 타일은 타일의 **오른쪽**(상점 창 안에서. 자리가 없으면 왼쪽), 인벤토리 격자의 아이템은 그 조각의 왼쪽(팝업 안에서)이다(`ShowBeside`에 합치기 안내를 함께 준다).
  화면 끝에 밀려 **자기 보드를 덮게 되면 보드의 반대쪽**에 선다(아군 넷일 때 4열·3열의 카드는 오른쪽. 이웃 보드를 잠시 덮는다 — 전투에서 보드는 누를 일이 없다). **옆 꼭지**(목업 6, 2026-10-07 사용자 "전투 툴팁에도 화살표"): 보드 쪽 옆면의 꼭지가 누른 칸의 세로 가운데를 가리킨다(모서리에서 16 안). 꼭지는 한 번에 하나다(아래·왼쪽·오른쪽).
- **동작**: 파티 쪽에서 아이템을 **좌클릭**하면 **집기만** 한다(금 조각, 합칠 조각의 표시, 설명 줄). **우클릭**은 든 것이 없을 때 그 칸의 아이템 카드를 열고(빈 칸은 열지 않는다. `PartySideView.ShowTooltip`), 든 동안은 든 것을 돌린다("격자 보드").

  폭풍 아이콘과 "폭풍까지 N초"(폭풍 뒤에는 "폭풍! 다음 피해 N", 글자가 화상의 색). 양초는 무대의 유일한 빛이기도 하다("무대의 빛 = 양초").
  최근 사건 세 줄의 **자막**은 헤더의 가운데에 있다(최신이 맨 아래에 밝게, 위로 갈수록 흐리게. 던전 이름과 층은 후퇴 버튼 옆으로 갔다). 자막은 로그 창이 아니라 짧은 문장이고,
  전투 중 로그 숨김 결정과 함께 사용자가 승인했다("연출").
- **편은 자리가 말한다**(아군 왼쪽, 적 오른쪽): 발밑 표시는 두 편이 같고, 보드 머리의 이름 색이 거든다(몬스터는 옅은 붉은 글). 상태는 막대의 테두리와 배지가 말한다. 큰 색 카드는 없다.
  열 이름을 머리 위에 따로 적지 않는다. 유닛이 전진하면 보드가 새 열로 가고 머리 띠의 열 번호가 바뀐다.
- 헤더와 포션 띠는 패널 그림 위에 있다. 버튼은 버튼 그림에 색을 입힌 것이다. 전투 시간과 폭풍은 패널 가운데의 시계에 있고, 헤더의 가운데는 자막 세 줄, 던전 이름과 층은 후퇴 버튼 옆이다.
  포션의 안내 판은 포션을 누른 동안만 띠 옆에 보이고(이름 · 효과 · 할 일. 판의 폭은 글자의 길이를 따른다), 쓰거나 내려놓으면 사라진다("야영지 장비"). 결과 Panel과 로그 보기도 같은 패널과 버튼 그림을 쓴다.
- 유닛은 **엔진이 말하는 지금의 열**의 Column에 있고, 그 보드는 패널의 같은 열의 column에 있다. 매 Frame 확인해서 열이 바뀐 유닛을 옮긴다(둘 다). 화면이 전진을 계산하지 않는다.
  쓰러진 용병의 무덤이 서 있는 동안만 파티를 옮기지 않고 기다린다("연출"의 "무덤이 서 있는 동안").
- 죽은 유닛은 무대에서도 패널에서도 치운다(패널의 column도 열이라, 전진한 유닛의 보드가 그리로 온다). 누가 죽었는지는 결과 Panel이 말한다.
- **전투 중에는 로그를 보여 주지 않는다** (2026-10-01 사용자 결정). 전투가 끝나면 결과 Panel의 "로그 보기"가 전체 로그를 연다:
  누가 쓰러졌는지 한 줄씩(아군, 적)과 이벤트 로그 전체를 스크롤로 본다(`UiBuild.VerticalScroll`. 긴 로그는 여러 Text로 나눈다).
  전투 중에 보이는 것은 헤더 가운데의 자막 세 줄뿐이다("연출").
- 주인이 선 자리에서 쓸 수 없는 아이템은 회색 조각에 회색으로 어두운 아이콘(이나 흐린 이름)이고 충전하지 않는다. 누가 죽어 자리가 달라지면 그 자리에서 바뀐다.
- `BattleClock`이 Frame 시간을 전투 밀리초로 바꾸고 `ExpeditionManager.AdvanceBattle`을 부른다. 배속(x1, x2, x4)과 정지는 보여 주는 속도일 뿐이다. 결정타 동안의 느림(`SlowPercent`, "연출")도 같다.
- 정지 중에도 포션과 후퇴를 입력할 수 있다.
- 매 Frame 다시 그리되, 숫자가 바뀐 글자만 다시 만든다.
- 전투가 끝나면 결과 Panel이 승패와 사망 설명(언제 빈사가 됐고, 유예가 어떻게 끝났고, 마지막 피격과 굴림이 무엇이었는지. 쓰러짐으로 죽었으면 피격과 굴림 대신 쓰러짐: "문구")을 보인다.
- 이어하기로 들어온 전투는 정지 상태로 연다. 플레이어가 상황을 보고 풀 수 있게 하기 위해서다.

## 연출 (2026-10-03, 조사 보고 뒤 "1·2·3차 권장안으로 진행")

전투 화면은 **일어난 일을 그 순간에 보여 준다.** 규칙은 하나다: 화면은 엔진이 이미 확정한 이벤트 로그를 읽어 연출하고, 연출은 아무것도 바꾸지 않는다
(CLAUDE.md §3: 연출 완료를 결과·저장·Bootstrap의 조건으로 쓰지 않는다). 연출의 시간은 Unity의 Frame 시간이지 전투 시간이 아니므로, 정지 중에도 떠오르던 숫자는 끝까지 떠오른다.
조사 보고와 레퍼런스(Darkest Dungeon, Slay the Spire, The Bazaar, Backpack Battles)는 `ArtPipeline/Archive/09-battle-ui-feel/README.md`.

- **읽는 방식** (`BattlePresenter`): 화면이 열릴 때 로그의 끝을 기억하고, 매 Frame 그 뒤에 쌓인 이벤트를 차례로 재생한다. 엔진 시각보다 `RecentMs`(300ms) 넘게 오래된 이벤트는 건너뛴다.
  이어하기로 들어온 전투와 Test가 한 번에 긴 구간을 보낼 때 과거를 다시 재생하지 않기 위해서다. 재생은 죽은 유닛을 치우기 전에 하므로 잔상과 무덤이 유닛이 서 있던 자리에서 시작한다.

- **발밑 표시는 제자리** (2026-10-04, Design/10 §5. 명패였을 때 정했다): 돌진·밀림은 그림과 발밑 그림자만 움직이고(`FigureView.SetMotion`), 발밑 표시(HP·배지·테두리·상태)는 열에 그대로 있어 싸우는 동안에도 읽힌다.

- **결정타** (2026-10-05 Round 30, Design/10 §5. 목업 `ArtPipeline/Archive/30-kill-moment/`): 적이 유닛의 아이템에 쓰러지면(`BattlePresenter`가 찾는다: 적의 `Died` 바로 앞의 `Damaged`가 유닛에게서 온 아이템의 것.
  적에게는 빈사가 없어 죽음은 그 피해 바로 뒤에 기록된다. 화상·폭풍·패시브는 아니다) 화면이 그 순간을 강조한다(`BattleScreen`의 `Kill*`. 틀은 `StageMoment`: 붕괴의 순간도 같은 틀을 쓴다, 위 표):
  - **0.5초**(x1의 실제 시간) 동안 전투 시계가 25%로 흐르고(`BattleClock.SlowPercent`. 플레이어가 고른 배속은 그대로) 움직임도 25%다(`Time.timeScale`. 화면이 닫히면 `OnDisable`이 되돌린다).
    결정타는 실제 시간으로 흘러 정지해도 끝난다. 포션은 그동안에도 쓸 수 있다(입력은 전투 시각에 적용된다). x2는 시간이 절반, x4에는 없다(`KillMomentTopSpeed`).
  - 쓰러진 적은 그동안 무대에 남고(피격 자세, HP 0) 적의 나머지는 자리를 지킨다(`Place`의 `hold`와 `kept`). 보드는 바로 사라진다(무덤과 같다).
  - **어둠**(`KillDark`: 무대의 상자를 덮는 검정. 승인한 60%는 목업의 것으로 화면의 밝기가 40%가 되는 어둠이다. UI는 선형 색공간에서 섞으므로 같은 어둠은 알파 0.87(1 - 0.4^2.2). 0.08초에 들고 0.45초부터 0.12초에 걷힌다)이 전장의 Column 사이에 있고, 그 위에 쓰러진 적의 Column, 맨 위에 친 유닛의 Column이 그려진다(`ArrangeColumns`).
  - **줌**: 무대의 뒤(`StageBack`: 배경과 양초의 빛)와 앞(`StageFront`: 전장)이 두 유닛의 그림 가운데를 중심으로 **1.1배**로 당겨졌다(0.12초) 0.45초부터 0.2초에 돌아온다. 둘 다 Frame에 펼쳐진 층이라 피벗을 그 점에 두면 움직이지 않고 배율만 바뀐다.
    헤더와 보드 패널이 그 위에 그려져 넘친 곳을 덮는다. 어둠은 줌을 되돌려 무대의 상자 그대로다. 떠오르는 글자는 Fx 층이라 당겨지지 않는다. 잔상과 무덤은 그림이 보인 크기를 따른다(`BattleFxLayer.ScaleOf`).
  - **떨림 없음**: 결정타의 큰 피해 떨림도 쓰러질 때의 떨림도 없다. 0.5초가 지나면 쓰러진 적은 "쓰러짐"과 함께 잔상이 되고, 적이 걸어간다. 같은 때 여럿이 쓰러지면 한 번에, 결정타 동안 또 쓰러지면 그 결정타에 더한다(시간은 늘지 않는다).
  - 마지막 적의 결정타가 끝난 뒤(줌이 돌아온 뒤)에 결과 창이 뜬다. Test는 `UiTestUtil.WaitForResult`, `WaitForTheKillMoment`로 기다린다.
- **무덤이 서 있는 동안** (2026-10-04 Round 21, Design/10 §5): 파티의 살아 있는 유닛은 그려진 자리(무대의 Column, 패널의 보드와 그 머리 띠의 열 번호)에 그대로 있다.
  무덤이 모두 사라지면(`BattleFxLayer.GravesLeft`가 0) 한 번에 엔진의 열로 옮겨 걸어간다(`BattleScreen.Place`의 `hold`). 엔진은 이미 전진했다: 타깃·범위·쓸 수 있는 자리는 새 자리의 것이고,
  기다리는 동안의 돌진·밀림·숫자는 그려진 자리에서 보인다(연출은 View의 자리에서 한다). 기다리는 동안 또 쓰러지면 그 무덤이 사라질 때까지 기다린다. 죽은 유닛은 기다리지 않고 바로 치운다. 적은 기다리지 않는다.
  배속으로 나누는 것은 연출이 Frame 시간이라 x4에서 0.85초를 기다리는 동안 전투가 3.4초 가기 때문이다. 결과 창은 Fx 층 위라 기다리는 동안 전투가 끝나도 무덤은 그 아래에서 끝까지 간다.
- **떠오르는 글자** (`FloatingTextView`, `BattleFxLayer.Float`): 유닛 그림 자리의 위 가운데에서 84 올라가며 뒤 45%에서 사라진다. 처음 0.14초는 1.35배로 튀어나오고 무거운 것은 1.4배다.
  뒤에 어두운 그림자 글자가 있어 어떤 배경에서도 읽힌다. 문구는 `Fx.*` Key다(코드에 글자를 적지 않는다).
- **생기**: 발밑 그림자와 숨쉬기("유닛의 그림"). HP 막대에는 잔상(`UiBarGhost`: 깎인 만큼 붉은 꼬리가 0.2초 뒤 초당 130%로 줄어든다. 쿨다운에는 없다).
- **폭풍**: 패널 가운데의 양초("디아블로 컨셉")가 폭풍까지 타들어 가고, 폭풍 10초 전부터 불꽃이 작아지며 무대의 빛이 줄어든다. 폭풍이 오면 불이 꺼져 무대가 어두워지고, 글자가 화상의 색이 되고 틱마다 번개가 친다.
  (2026-10-03의 시계 고리와 "어스름" 비네트(`BattleFxLayer.SetStorm`)는 양초와 그 빛이 대신했다.)
- **흔들림**: 무대(`Field`)의 anchoredPosition을 흔들고 되돌린다(`BattleFxLayer.Shake`). 패널과 헤더는 흔들지 않는다.
- **Fx 층**(`Fx`): 무대와 패널 위, 결과 창과 로그 창 아래. 빈사의 붉은 비네트와 번개는 무대의 상자(헤더 아래부터 패널 위까지)에만 깔린다. 잔상과 무덤은 같은 틀(`GhostTemplate`)로 만든다. 아무것도 클릭을 받지 않는다.
- Tween 패키지를 들이지 않는다. 움직임은 각 View의 `Update`에서 Frame 시간으로 계산한다.

  (`Battle_AMercenaryShowsItsAttackPoseWhileItsWeaponLunges_AndItsHitPoseWhileItRecoils`, `Battle_AnEnemyShowsItsAttackPoseWhileItsWeaponLunges_AndItsHitPoseWhileItRecoils`).
  공격하는 유닛의 Column은 공격하는 동안 맨 위이고 끝나면 원래 순서다(`Battle_AnAttackerIsDrawnInFrontOfEveryone_WhileItAttacks`). 지원 아이템의 맥동은 빛을 켜고 그림을 부풀렸다가 0.3초 뒤 끈다(`Battle_ASupportItemPulsesItsOwner_WithALightBehind`).
  분류마다 움직임(`ItemMotionTests`)과 출고 아이템의 분류(`ShippedDataTests.ShippedItems_AreClassedAsDecided`)는 EditMode. 모양은 스크린샷(`ko_23_battle_attack_pose`, `ko_24_battle_hit_pose`, `ko_25_battle_support_pulse`, 보스전의 `ko_26_battle_boss_attack_pose`, `ko_27_battle_back_row_attack`, `ko_28_battle_enemy_hit_pose`).
- 쿨다운: 첫 발동 전(0.7초)에 조각마다 아이콘이 충전만큼 왼쪽부터 밝다. 충전 전에는 다 어둡고, 다 차면 다 밝고, 충전하지 않는 아이템은 어둡다. 발동하면 다 밝은 채 커지고(한 프레임 20 ms로 고정해 잰다. 1.12배를 넘지 않음)
  0.4초 뒤 제 크기로 돌아와 충전만큼만 밝다. 용병의 보드는 가방과 빈 칸을, 적의 보드는 둘 다 보이지 않는다(`Battle_ItemCells_StartDark_AndLightUpFromTheLeftAsTheyCharge`). 빛의 모양과 세기는 스크린샷으로 본다.
- EditMode: `FieldLayout`이 전장을 빈틈없이 채우고, 같은 편의 Column이 서로 겹치지 않고, 두 편 사이가 같은 편 사이보다 넓다.
- 발밑 표시: 배지가 엔진의 상태를 따른다(빈사면 해골, 보호막이면 방패와 그 수, 아니면 없음). 포션을 고르면 아군의 테두리가 포션 대상이 되고 발밑에 빛이 깔리며 적은 아니다(포션 Test).
  빈사면 빨간 테두리와 숫자 없는 해골이고 상태 줄에는 빈사만 보인다(`Battle_AUnitAtDeathsDoor_ShowsItUnderItsFeet`). 보드의 머리 띠는 유닛이 선 열과 이름을 말하고 몬스터의 이름은 붉은 글이다(그림 Test).
  파티 쪽의 머리 띠는 그 열의 번호와 용병의 이름을 말한다(파티 쪽 Test).
  빈사는 운에 맡기지 않게 Test가 파티를 약하게 만들어 첫 전투에서 만든다.
- 툴팁(Round 42, 우클릭은 Round 47, 격자는 19단계): 파티 쪽에서 든 것이 없을 때 아이템의 어느 칸을 우클릭해도 카드가 패널 위 8에 그 조각에 맞춰 뜨고(제목·사실·효과·피로·합치기 안내가 `UiText`의 것과 같다. 꼭지 폭은 조각의 폭), 아무 데나 누르면 카드만 닫힌다.
  좌클릭은 집기만 하고 카드는 열리지 않으며, 든 동안의 우클릭도 카드를 열지 않는다(돌리기). 빈 칸은 열리지 않으며, 카드가 열린 채 집는 클릭은 카드를 닫는다(`PartySide_RightClickingAnItem_OpensItsCardAboveThePanel_AndTheNextPressClosesOnlyTheCard`).
  전투에서 적의 칸을 우클릭하면 카드가 보드 오른쪽 10에 왼쪽 옆면의 꼭지가 칸의 가운데 높이를 가리키고(좌클릭은 아무것도 열지 않는다), 아군의 칸은 왼쪽(자리가 없으면 오른쪽)에 보드 쪽 꼭지로 뜨며(전투는 그대로), 포션을 들면 칸이 클릭을 받지 않는다(`Battle_RightClickingAnItem_OpensItsCardBesideTheBoard_PartyLeftEnemyRight_NotWhileAPotionIsArmed`).
  자리의 산술은 EditMode(`TooltipPlacementTests`). 모양은 스크린샷(`ko_40_battle_item_card`: 보스전의 적 카드). 격자의 모양은 스크린샷 `_08_map_item_selected`(든 무기와 그림자), `_30_map_fatigue`, `_35_map_tiers`(합치기 그림자), `_44_map_turned`(돌린 그림자), `_45_map_bag_held`(든 가방과 틀), `_49_map_inventory_open`(인벤토리의 조각과 선), `_50_map_inventory_ghost`(인벤토리 위의 한 덩어리 그림자).
- 방금 켜진 Panel은 Canvas가 한 번 그린 뒤에야 Raycast에 잡힌다. Test는 Panel을 켠 뒤 `UiTestUtil.WaitForRedraw`를 기다린다.
- 눈으로 확인: `Tools/screenshots.sh`가 모든 화면을 두 Locale로 PNG로 뽑는다(저장소 밖). 그래픽 장치가 필요해서 체인에는 넣지 않는다.
- 레이아웃, 읽기 쉬움, 손맛은 자동 Test로 판정하지 않는다. 스크린샷과 수동 플레이로 본다.

## Validation

- 화면이 규칙을 계산하지 않는가? 상태 객체를 직접 바꾸지 않는가?
- 새 화면이 `ScreenCatalog`, Builder, `UiFlowTests`에 있는가? (상점은 `UiFlowTests`의 `Shop_...`과 스크린샷 `_41`~`_43`.)
- 새 문구가 CSV와 `UiKeys`에 있고, 코드에 표시 문구가 직접 들어가지 않았는가?
- Prefab을 손으로 고치지 않았는가? setup을 두 번 돌려도 Prefab이 바뀌지 않는가?

## Deferred and Forbidden

- Deferred: 포션의 아이콘, 인벤토리 팝업의 아이콘(그 UI를 그릴 때), 바닥의 전리품의 그린 빛·판(지금은 도형), 원정 화면 말고의 UI 그림(타이틀, 로비, 정산)과 노드 맵 오른쪽의 그림, 다른 화면의 배경, 전투 밖의 연출(화면 전환, 로비·정산),
  키보드 단축키와 패드, 설정 화면, 화면 전환 효과, 해상도 설정 UI. (툴팁은 2026-10-07 Round 42에 아이템 카드로 들어왔다: "툴팁: 아이템 카드".)
- Forbidden: UI에서 규칙 계산, 연출 완료를 명령의 조건으로 쓰기, Prefab 수작업 편집, legacy `Text`, 코드에 표시 문구 직접 쓰기,
  화면이 Addressables를 직접 부르기.

# 12. UI

`UIManager`, 화면(Screen)과 View, 화면 Prefab을 만드는 Setup 코드, UI Test를 소유한다.
문구와 Font는 `06_LOCALIZATION.md`, 게임 단계와 명령은 `11_APPLICATION_FLOW.md`, Address와 Scope는 `04_RESOURCES_ADDRESSABLES.md`가 소유한다.

## 구조

```text
Assets/@Scripts/UI              Namespace F1.UI
├─ UIManager        화면 하나를 Main Scene의 UI Root에 띄운다
├─ UIScreen         화면의 Base. ScreenId, ScreenCatalog (Address, Scope, 단계 -> 화면)
├─ Screens/         TitleScreen, LobbyScreen, NodeMapScreen, BattleScreen, RewardScreen, SettlementScreen
├─ Views/           화면 안의 조각: RosterEntryView, PartySideView, PartyColumnView, BattleUnitView, UiBar ...
├─ UiKeys, UiStrings, UiText, BattleLogText     문구
└─ UiPalette        색

Assets/@Scripts/Editor/Setup/Ui   UiBuild(도구), UiPrefabSetup.*(화면별 Builder)
Assets/@Prefabs/UI                <ScreenId>Screen.prefab, SaveErrorOverlay.prefab, UiPrefabStamp.txt (생성물)
```

## 화면의 역할

- 화면은 **상태를 보여 주고 명령을 전달한다.** 규칙을 계산하지 않는다. 명령이 가능한지는 Manager에 묻는다
  (`CanDepart`, `CanPlaceInParty`, `CanMoveToRow`, `AvailableNodes`, `CanUsePotion`).
  어느 열에 설 수 있는지도 규칙이다. 화면은 열마다 물어서 버튼을 켜고 끈다.
- 화면은 `Managers`를 통해 `RunManager`, `ExpeditionManager`, `SettingManager`, `DataManager`를 쓴다. 상태 객체를 직접 바꾸지 않는다.
- 명령을 낸 뒤에는 상태를 다시 읽어 그린다(`Refresh`). 단계가 바뀌었을 수 있으면 `GoToCurrentPhase`를 부른다.
- 화면은 한 번에 하나다. 팝업은 화면 Prefab 안의 Panel을 켜고 끄는 것으로 한다(확인, 결과, 런 종료).
- 연출 완료를 기다려 명령을 내지 않는다. 전투 결과와 정산은 이미 확정돼 있고(`11_APPLICATION_FLOW.md`), 화면은 그것을 보여 줄 뿐이다.

| 화면 | 단계 | Scope | 하는 일 |
|---|---|---|---|
| `TitleScreen` | 앱을 켰을 때, 로비에서 타이틀로 나왔을 때 | App | 새 런(진행 중이면 확인), 이어하기, 언어, 종료, Save 파일 상태 알림 |
| `LobbyScreen` | `Lobby` | Lobby | 날짜, 로스터와 피로도, 파티와 열(용병마다 열 버튼과 제외), 쉬기, 출발, 런 종료 안내 |
| `NodeMapScreen` | `NodeMap` | Expedition | 맵과 노드 선택(적은 보이지 않는다 → `Docs/Design/03` §1), 파티 쪽(전투와 같은 열), 포션, 인벤토리 팝업 |
| `BattleScreen` | `Battle` | Expedition | 전투 진행(배속, 정지), 유닛(그림 자리와 정보 카드), 포션, 후퇴, 결과와 사망 설명, 끝난 뒤의 로그 보기 |
| `RewardScreen` | `Reward` | Expedition | 보상 고르기(보드의 칸이나 인벤토리로), 파티 쪽(전투와 같은 열), 포션, 인벤토리 팝업 |
| `SettlementScreen` | `Settlement` | Expedition | 귀환 정산 보고 |

## UIManager

- `ShowAsync(ScreenId)`: 새 화면을 만들어 `Open`한 뒤 이전 화면을 놓는다. 그 사이 빈 Frame이 없다.
- 바꾸는 동안 이전 화면은 클릭을 받지 않는다. 같은 명령이 두 번 나가지 않게 하기 위해서다. 바꾸는 중에 또 부르면 예외다.
- 화면의 Scope만 열어 둔다. Lobby 화면을 떠나면 Lobby Scope를, 원정 화면들을 떠나면 Expedition Scope를 놓는다.
- Boot의 마지막 단계(BOOT-12)가 타이틀을 띄운다.
- `SaveErrorOverlay`는 화면이 아니다. `BindAsync`에서 한 번 만들어 앱이 끝날 때까지 모든 화면 위에 둔다.
  저장이 막히면(`RunManager.SaveBlockedChanged`) 화면 전체를 가리고 "다시 시도"와 "종료"만 받는다.

## 화면 Prefab은 코드로 만든다

- Prefab을 손으로 고치지 않는다. `Editor/Setup/Ui`의 Builder를 고치고 setup을 돌린다.
- 1920x1080 설계 공간에 좌표로 배치한다(`UiBuild.Box`). Canvas는 Expand라서 어떤 화면 비율에서도 이 영역이 잘리지 않는다.
- 목록(로스터, 노드, 유닛, 아이템 칸)은 Prefab 안의 꺼진 Template을 Runtime에 복제한다.
- 직렬화 참조는 Builder가 이름으로 채운다(`UiBuild.SetReference`). 빠뜨린 참조는 `UiPrefabSetup.FindProblems`가 잡는다.
- **한 Prefab 안의 모든 Object 이름은 달라야 한다.** Unity는 다시 만든 Prefab의 id를 이름으로 맞추기 때문에, 이름이 겹치면 만들 때마다
  파일이 바뀐다. 겹치면 Builder가 실패한다.
- Builder 코드(와 `UiPalette`)가 바뀌었을 때만 다시 만든다. `UiPrefabStamp.txt`가 Builder 소스의 Hash를 기록한다.
  CSV 문구를 고쳐도 Prefab은 바뀌지 않는다(고정 라벨은 Prefab에 Key를 담고, 문구는 Runtime에 String Table에서 온다).
- 그림은 도형 Placeholder다(색 사각형). 막대는 Sprite 없이 폭으로 그린다(`UiBar`).

## 문구

- 고정 라벨: Builder가 `UiBuild.LocalizedLabel`로 만든다. 자리(`{0}`)가 있는 Key는 쓸 수 없다.
- 값이 들어가는 문구: 화면이 `UiStrings.Get(UiKeys.X, 값)`으로 만든다. `UIScreen`이 `LocaleChanged`를 듣고 `Refresh`를 부른다.
- Game Data의 이름: `UiText.Name(LocalizedText)`. 아이템과 포션의 설명은 효과 어휘에서 조립한다(`UiText`). 직업 패시브 설명은 데이터가 가진다.
- 전투 로그와 사망 설명은 `BattleLogText`가 이벤트 로그에서 만든다. 사망 원인을 읽는 것은 Domain의 `BattleLog.PartyDeaths`다.

## 열을 보여 주는 방식

- 열의 이름은 고정 라벨이다(`Common.Row1`~`Row4`, `UiText.RowKey`). 열의 수는 구조라서 Builder가 `BattleRows.Count`만큼 만든다.
- **파티가 설 수 있는 열의 수는 `PartySize`**이고 데이터다(지금은 한 쪽의 열 수와 같은 넷). 파티의 열에 딸린 것
  (로비의 열 버튼과 파티 줄, 전투 화면의 아군 Column)은 Prefab에 `BattleRows.Count`만큼 있고, `PartySize`가 그보다 적으면 화면이 열 때 넘는 것을 감춘다.
- 로비: 로스터의 용병마다 열 버튼과 "제외"가 있다. 설 수 있는 열만 켜진다. 서 있는 열의 버튼은 강조되고, 눌러도 바뀌는 것이 없다.
- 아이템 설명은 크기와 쓸 수 있는 자리(앞이나 뒤에서 몇 번째까지)를 적는다. 어디서나 쓸 수 있으면 자리는 적지 않는다.

## 파티 쪽: 노드 맵과 보상 화면 (2026-10-01 목업으로 승인한 "C안")

노드 맵과 보상 화면의 왼쪽은 **전투 화면의 아군 쪽과 같은 자리, 같은 모양**이다(`PartySideView`). 세 화면에서 파티가 같은 그림으로 보이게 하기 위해서다.

- 열마다 Column이 하나씩, 전투와 같은 자리에(4열, 3열, 2열, 1열. 1열이 오른쪽). 위에서 아래로 열 이름, **그림 자리**(전투와 같은 전신 실루엣 Placeholder),
  바닥선, **정보 카드**(이름, 직업, HP, 앞으로와 뒤로), 그리고 카드 안에 **아이템 칸을 세로로** 쌓는다(`PartyColumnView`).
  아이템은 크기만큼 칸을 이어서 차지하고(한 View가 높아진다), 빈 칸은 흐린 칸이다. 카드의 높이는 `JobData.MaxItemSlots`칸 분량으로 고정이다.
- Column은 **살아 있는 용병이 선 열**에만 보인다. 죽은 용병은 전투에서처럼 보이지 않는다(죽은 것은 정산이 말한다).
  파티가 설 수 없는 열(`PartySize` 밖)은 감춘다.
- "앞으로"는 1열 쪽(오른쪽)으로, "뒤로"는 그 반대로 옆 열의 용병과 자리를 맞바꾼다. 자리가 바뀌면 Column의 내용이 바뀐다.
- **포션**은 전투와 같은 자리(헤더 아래 왼쪽의 띠)에 있다. 노드 맵과 보상에서는 보여 주기만 한다(쓰는 것은 전투, 받는 것은 보상 카드).
- 조작은 "누르고 누르기"다. 보드의 아이템을 누른 뒤 다른 칸을 누르면 옮기거나 서로 바꾸고, "인벤토리로"(파티 아래)를 누르면 인벤토리로 빠진다.
  같은 것을 다시 누르면 고른 것을 푼다. 할 수 없는 곳은 눌리지 않는다: 칸마다 Manager에 묻는다(`CanPickItem`, `CanMoveItem`, `CanPlaceFromInventory`, `CanPlaceReward`).
- 아무것도 고르지 않았을 때는 안내문이, 골랐을 때는 그 아이템의 설명이 파티 아래 한 줄에 보인다.

### 인벤토리 팝업

- 인벤토리는 줄이 아니라 **팝업**이다. "인벤토리 보기"를 누르면 화면 오른쪽(맵, 또는 보상 목록)을 덮는 세로 목록이 열리고 버튼은 "인벤토리 닫기"가 된다.
  목록의 한 줄은 아이템 이름·등급과 설명 요약이다. 비어 있으면 "비어 있음"만 보인다. 길면 스크롤이다.
  제목은 쓴 칸과 전체 칸이다("인벤토리 (3/10칸)". 칸은 `BalanceData.InventoryCells`, 아이템은 크기만큼).
- 인벤토리에 자리가 없으면 그리로 가는 버튼이 꺼진다: 보상 화면의 "인벤토리에 넣기"(`CanTakeRewardToInventory`), 파티 아래의 "인벤토리로"(`CanMoveToInventory`),
  그리고 밀려나는 아이템이 들어가지 못하는 찬 칸. 보드의 아이템을 집어 다른 보드로 옮기는 것은 인벤토리가 차도 된다(`CanPickItem`).
- 팝업의 아이템을 누른 뒤 왼쪽 보드의 칸을 누르면 들어간다(찬 칸이면 그 아이템이 인벤토리로 온다). 팝업은 열린 채다.
- 고르는 것은 한 번에 하나다: 보드의 아이템, 인벤토리의 아이템, (보상 화면의) 보상 아이템 가운데 하나만 금색이다. 다른 것을 고르면 앞의 선택은 풀린다.
- 노드 맵의 버튼은 노드 정보 패널에("전투 시작" 옆), 보상 화면의 버튼은 아래 버튼 줄에("인벤토리에 넣기" 옆) 있다.

### 노드 맵의 오른쪽

- 맵이 오른쪽을 거의 다 쓴다. 그 아래 노드 정보 패널에는 고른 노드의 층과 종류, 적은 보이지 않는다는 안내, "인벤토리 보기", "전투 시작"뿐이다.
  적 무리를 미리 보여 주지 않는 것은 기획 규칙이다(`Docs/Design/03_Dungeon_Structure.md` §1).

### 보상 화면의 오른쪽

- 보상 셋을 위아래로 쌓는다. 보상 아이템을 고른 동안에는 왼쪽 보드의 칸이 "그 보상을 넣을 수 있는 곳"으로만 켜지고(`CanPlaceReward`),
  인벤토리 팝업의 아이템과 "인벤토리로"는 꺼진다. 아래 버튼 줄은 "인벤토리에 넣기"(고른 보상을 인벤토리로 바로), "인벤토리 보기/닫기", "넘기기"다.

## 전투 화면

위에서 아래로: 헤더(후퇴, 시간, 폭풍, 정지와 배속), 그 아래 왼쪽에 포션과 안내, 비워 둔 상단 여백(배경 그림 자리), 전장.
2026-10-01 사용자가 목업(C안)으로 승인한 배치다. 다키스트 던전처럼 배경 위에 전신 캐릭터가 서는 무대를 전제한다.

- 양쪽에 열마다 Column이 하나씩 있고, Column에는 유닛이 하나 들어간다. 가운데에서 두 1열이 마주 본다
  (아군 4열, 3열, 2열, 1열 | 적 1열, 2열, 3열, 4열).
- Column의 자리와 폭은 화면이 열 때 정한다(`BattleScreen.LayoutColumns`): 아군 Column은 `PartySize`개, 적 Column은 `BattleRows.Count`개를
  전장 폭에 고르게 편다. 유닛은 Column의 폭을 따른다. 그래서 유닛 안의 요소는 좌표가 아니라 가로로 늘어나는 줄(`UiBuild.Line`)로 만든다.
- 유닛(`BattleUnitView`)은 **그림 자리**와 **정보 카드**로 되어 있다. 그림 자리는 바닥선 위에 선 전신 실루엣 도형(Placeholder. 9단계에서 그림으로 바뀐다)이고,
  카드는 이름, 빈사 상태, HP, 보호막과 화상, 그리고 아이템 보드다. 어느 쪽을 눌러도 그 유닛을 누른 것이다(포션 대상).
- 아이템 보드는 세로로 쌓인 칸이다. 유닛의 칸 수(`ItemSlots`. 적은 가진 아이템의 크기 합)만큼 그리고, 아이템은 크기(`Size`)만큼 칸을
  이어서 차지하며(`BattleItemView.Bind`의 칸 수), 빈 칸은 흐린 칸으로 둔다.
  칸 하나는 쿨다운이 차오르는 바이고, 그 뒤에 첫 효과의 종류를 뜻하는 도형 아이콘(피해 ◆, 회복 ✚, 보호막 ■, 화상 ●. Placeholder)이 있다.
  카드의 높이는 `JobData.MaxItemSlots`칸 분량으로 고정이다.
- 유닛은 **엔진이 말하는 지금의 열**의 Column에 있다. 매 Frame 확인해서 열이 바뀐 유닛을 옮긴다. 화면이 전진을 계산하지 않는다.
- 죽은 유닛은 치운다. 누가 죽었는지는 결과 Panel이 말한다.
- **전투 중에는 로그를 보여 주지 않는다** (2026-10-01 사용자 결정). 전투가 끝나면 결과 Panel의 "로그 보기"가 전체 로그를 연다:
  누가 쓰러졌는지 한 줄씩(아군, 적)과 이벤트 로그 전체를 스크롤로 본다(`UiBuild.VerticalScroll`. 긴 로그는 여러 Text로 나눈다).
  로그가 있던 오른쪽 아래 Panel은 비워 둔다. 용도는 정해지지 않았다.
- 주인이 선 자리에서 쓸 수 없는 아이템은 흐리게 그리고 쿨다운 막대를 비운다. 누가 죽어 자리가 달라지면 그 자리에서 바뀐다.
- `BattleClock`이 Frame 시간을 전투 밀리초로 바꾸고 `ExpeditionManager.AdvanceBattle`을 부른다. 배속(x1, x2, x4)과 정지는 보여 주는 속도일 뿐이다.
- 정지 중에도 포션과 후퇴를 입력할 수 있다.
- 매 Frame 다시 그리되, 숫자가 바뀐 글자만 다시 만든다.
- 전투가 끝나면 결과 Panel이 승패와 사망 설명(언제 빈사가 됐고, 유예가 어떻게 끝났고, 마지막 피격과 굴림이 무엇이었는지)을 보인다.
- 이어하기로 들어온 전투는 정지 상태로 연다. 플레이어가 상황을 보고 풀 수 있게 하기 위해서다.

  켜져 있고, 다른 것에 가려지지 않았는지(Pointer Raycast) 확인한 뒤 누른다.
- 열에 관한 화면 동작도 버튼으로 확인한다: 로비의 열 버튼(넣기, 맞바꾸기, 제외), 파티 쪽 Column의 앞으로와 뒤로(내용이 옆 열로 옮겨 가는 것),
  전투에서 열이 비었을 때 카드가 옮겨지는 것, 파티가 서지 않는 열이 감춰지는 것, 전투가 끝난 뒤 로그 보기에 죽은 유닛과 전진이 적히는 것.
  전투의 전진은 운에 맡기지 않게 Test가 1열 용병을 직접 강하게 만들어 보스전까지 간다.
- 보드와 인벤토리도 버튼으로 확인한다: 보상을 인벤토리로 받기, 팝업을 열어 아이템을 고르고 보드의 찬 칸에 넣어 원래 아이템이 인벤토리로 가는 것,
  보드의 아이템을 "인벤토리로" 빼는 것, 넣을 수 없는 칸이 눌리지 않는 것, 팝업이 닫히면 고른 것이 풀리는 것,
  제목의 칸 수, 인벤토리가 가득 찼을 때 "인벤토리로"는 꺼지고 다른 보드의 빈 칸은 켜지는 것.
- 방금 켜진 Panel은 Canvas가 한 번 그린 뒤에야 Raycast에 잡힌다. Test는 Panel을 켠 뒤 `UiTestUtil.WaitForRedraw`를 기다린다.
- 눈으로 확인: `Tools/screenshots.sh`가 모든 화면을 두 Locale로 PNG로 뽑는다(저장소 밖). 그래픽 장치가 필요해서 체인에는 넣지 않는다.
- 레이아웃, 읽기 쉬움, 손맛은 자동 Test로 판정하지 않는다. 스크린샷과 수동 플레이로 본다.

## Validation

- 화면이 규칙을 계산하지 않는가? 상태 객체를 직접 바꾸지 않는가?
- 새 화면이 `ScreenCatalog`, Builder, `UiFlowTests`에 있는가?
- 새 문구가 CSV와 `UiKeys`에 있고, 코드에 표시 문구가 직접 들어가지 않았는가?
- Prefab을 손으로 고치지 않았는가? setup을 두 번 돌려도 Prefab이 바뀌지 않는가?

## Deferred and Forbidden

- Deferred: 실제 그림과 연출, 소리, 키보드 단축키와 패드, 설정 화면, 툴팁, 화면 전환 효과, 해상도 설정 UI.
- Forbidden: UI에서 규칙 계산, 연출 완료를 명령의 조건으로 쓰기, Prefab 수작업 편집, legacy `Text`, 코드에 표시 문구 직접 쓰기,
  화면이 Addressables를 직접 부르기.

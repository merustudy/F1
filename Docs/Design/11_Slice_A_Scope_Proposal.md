# Slice A 범위 후보 제안 (【제안】, v0-recon)

> 2단계에서 작성할 09_VERTICAL_SLICE.md 의 **입력**이다. 그대로 채택하지 않는다.
> 전투 한 판을 세로로 관통하는 것을 Slice A 로 제안한다.
>
> 【확정】 (2026-09-30) Slice A는 **핵심 루프 한 바퀴 + 저장**으로 결정됐다. 범위는 Docs/Architecture/09_VERTICAL_SLICE.md 가 소유한다.
> 이 문서는 전투 부분의 입력으로만 쓴다. 포션/후퇴는 Slice A에 포함한다. `sim.py`가 없으므로 "기준 구현과 일치"는
> "같은 시드와 입력으로 반복 실행하면 결과가 같다"로 읽는다.

## 1. 목표
오토 전투 한 판이 게임 품질로 동작하고, 같은 시드에서 기준 구현(09 §2)과 결과가 일치함을 증명한다.

## 2. 포함
- **파티**: 전직 직업 3명. 패시브가 확정된 조합 우선 (예: knight 전열 + bishop + spellblade)
- **적**: 한 지역, 일반 전투 1~2종 + 보스 1 (B급, Lv9)
- **지역 속성**: 1종 (swift −8% — 값이 확정된 속성)
- **시스템**: 쿨다운 순환, 전열/후열, 피해·회복·보호막·화상, DoG 판정, 영구 사망
- **결정론**: 시드 리플레이
- **표현**: 도형 Placeholder. 흉상 초상화 자리, 아이템 보드 슬롯 + 쿨다운 게이지, HP·보호막·DoG 상태, 전투 로그
- **검증**: 같은 시드로 결과 == 기준 구현 (자동 테스트, 검증 체인에 포함)

## 3. 제외
- 로비, 100일, 경제, 성장, 던전 노드 맵
- 유물 (선택: 위치 조건 유물 1개로 전열/후열 판정만 검증)
- 포션/후퇴 — 【미결】. 입력 이벤트를 받을 구조적 자리만 열어 둔다
- 실제 아트, 소리 (로드맵 9·10단계)

## 4. 착수 전 결정 · 확보
1. `sim.py`, `prototype_data.json` 확보 — 없으면 02 문서의 【원본확인】 전투 규칙을 먼저 재정의하고 시뮬로 재검증
2. sim.py 와 C# Domain 의 관계 (09 §2)
3. 데이터 원천 형식 (09 §3)
4. 포션/후퇴를 Slice A 에 넣을지

## 5. 완료 기준
- 한 판이 처음부터 끝(승리/전멸)까지 자동 진행
- 같은 시드 10회 실행 → 결과 동일
- 기준 구현과 대조 결과 일치 (승패, 틱 수, 생존자 HP)
- 플레이어가 화면만 보고 "왜 죽었는지" 설명할 수 있음 (로그 + 상태 표시)

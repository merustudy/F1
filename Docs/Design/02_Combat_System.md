# 전투 시스템 상세설계 (재구성 v0-recon)

## 1. 개요
- 【확정】 The Bazaar식 **보드 슬롯 오토 전투**. 각 유닛이 장착한 아이템(카드)이 각자의 쿨다운에 따라 자동 발동하며 순환한다.
- 【확정】 전투는 **결정론적**이다 (→ 09_Implementation_Constraints). 같은 시드 + 같은 입력 = 같은 결과.
- 【확정】 (2026-09-30) **C# Domain이 전투의 기준 구현**이다. `sim.py`는 없다. 시뮬은 같은 Domain 코드를 Unity 밖에서 실행한다 (→ 09_Implementation_Constraints §2).

## 2. 참가자와 배치
- 아군: 용병 3인 (원형 전사·성직자·마법사 → 전직 6종)
- 적: 일반 적, 보스(B = Lv9, C = Lv13), 최종 보스(Lv14 전용)
- 【확정】 전열/후열 조건은 권장 열이 아니라 **실제 위치**로 판정 (`Battle.is_front` / `Battle.is_rear`)
- 【확정 — 시뮬】 전열 전사는 지역 속성과 무관하게 사실상 필수
- 【원본확인】 열당 슬롯 수, 타깃 선정 규칙, 적 편성 규모

## 3. 시간 모델과 쿨다운
- 【확정】 아이템은 쿨다운으로 순환 발동
- 【원본확인】 시간 단위(틱/초), 첫 발동 시점, 동시 발동 처리 순서
- 【제안】 원본 규칙이 없으면: 정수 틱 고정 스텝 + 동시 발동은 안정 정렬(진영 → 슬롯 인덱스 → id)

## 4. 아이템 (전투 카드)
- 【확정】 던전 안에서만 존재, **던전 종료 시 소멸**
- 【확정】 아이템에는 등급(grade)이 있다 (예: 소드 grade 12)
- 【확정 — 시뮬】 적 레벨이 아이템 등급 상승 임계값을 넘으면 사망이 급증 (Lv14에서 사망 ×5) → Lv14는 최종 보스 전용
- 【확정】 직업별 기본 무기 존재 — spellblade = 소드 grade 12. 나머지 【원본확인】
- 【원본확인】 효과 타입 목록, 슬롯 크기, 던전 내 획득 방식

## 5. 피해 · 회복 · 상태
- 회복 — 【확정】 존재
- 보호막 — 【확정】 존재 (bishop 패시브). 흡수 규칙 【원본확인】
- 화상(burn) — 【확정】 spellblade 무기 적중 시 화상 +3. 틱 피해·중첩·지속 【원본확인】
- 【원본확인】 피해 공식, 방어/저항, 치명타 유무

## 6. Death-or-Glory (사망 판정)
- 【확정 — 시뮬】 주 사망 원인은 HP 소모가 아니라 **DoG 판정**이다.
- 【확정】 **유예 기간(grace period)**이 있다. 적 공격 빈도가 올라 유예 기간 안에 받는 타격이 임계를 넘으면 사망이 비선형으로 급증한다 (swift −15%에서 사망 ×10).
- 【해석】 HP 0 도달 → DoG 상태 → 이후 피격 시 사망 확률 판정 (Darkest Dungeon의 Death's Door와 유사)
- 【확정】 설계 함의: 회복보다 **DoG 발동을 막거나 완충하는 효과**가 더 가치 있다 → bishop 패시브 변경 근거
- 【원본확인】 판정 확률, 유예 시간, DoG 해제 조건, 난수 소비 순서

## 8. 지역 속성의 전투 영향

| id | 값 | 적용 대상 | 비고 |
|---|---|---|---|
| swift | −8% | 【해석】 적 쿨다운 (공격 빈도 ↑) | −15%는 사망 ×10으로 기각 |
| hardened | −15% | 【원본확인】 | −25%에서 하향 |
| regen | 【원본확인】 | 【원본확인】 | |
| warded | 【원본확인】 | 【원본확인】 | |
| armored | 【원본확인】 | 【원본확인】 | |

- 【확정】 속성은 파티 구성을 유도하는 데 실패 → **난이도 조절 레버**로 재정의

## 9. 최종 보스 — Abyss Lord
- 【확정】 HP 420, 무기 로드아웃, 스켈레톤 호위, 3 페이즈 (HP 75% / 50% / 25% 기준)
- 【확정】 Lv14 (적 Lv14는 최종 보스 전용)
- 【확정】 100일 런 승률 약 82% (밸런스형) / 약 75% (안전형)
- 【원본확인】 로드아웃 구성, 페이즈별 변화, 호위 구성

## 10. 플레이어 개입 — 도입 【확정】, 세부 【미결, 임의 해결 금지】
- 【확정】 (2026-09-30) **포션 슬롯**(전투 중 사용)과 **후퇴**를 도입한다. Slice A에 포함한다.
- 제안된 형태: 포션 슬롯 최대 3 + 확률형·쿨다운 제한 후퇴 (수치와 형태는 세부와 함께 확정)
- 동기: 전투 중 플레이어의 무력감 해소
- 2026-09 논의: 오토배틀이 기본, 필요하면 수동 개입 허용 가능. 영구 손실에 대한 책임이 핵심
- 【확정 — 분석】 결정론과 실시간 입력은 양자택일이 아니다. 입력을 **타임스탬프 이벤트**로 기록하면 (시드 + 입력열 = 같은 결과) 시뮬 툴체인을 유지할 수 있다.
- 【미결】 남은 결정: 포션 효과·획득 / 후퇴 확률·쿨다운·결과 / 시뮬 AI의 입력 모델

## 11. 결정론 요구사항
- 【확정】 같은 시드 + 같은 입력 이벤트열 = 같은 결과
- 【제안】 난수는 시드 RNG 하나(또는 용도별 스트림)에서만 소비
- 【제안】 부동소수점 대신 정수/고정소수점
- 【제안】 검증: 같은 시드와 같은 입력으로 반복 실행한 결과가 같은지 확인하는 자동 테스트 (`sim.py`가 없으므로 구현 간 대조는 하지 않는다)
